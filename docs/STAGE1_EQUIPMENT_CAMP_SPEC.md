# STAGE1_EQUIPMENT_CAMP_SPEC — 装备构筑、背包与营地成长规格

> **版本：** v1.0  
> **日期：** 2026-11-12  
> **状态：** 已确认设计方向的系统规格；具体物品数值、掉率与经济价格待平衡  
> **适用范围：** 首版装备、局内背包、仓库、营地整备、兑换与永久解锁  
> **依据：** GAME_SCOPE.md v1.4、GAME_DESIGN_SPEC.md v2.1、STAGE1_CONFIRMED_DESIGN_BASELINE.md v1.0、DECISIONS_LOG.md v4.6  
> **决策：** D-205、D-206 已确认；不新增玩法决策。持久化技术实现仍由 D-207 阶段2 Spike 决定。

## 1. 设计目标与边界

装备系统的核心价值是改变玩家的战斗选择与构筑方向，而非只堆叠攻击/生命数字。营地负责将成功撤离所得转化为下一局的装备选择和有限永久解锁。

首版必须保持：
- 易于手机端查看、拾取、装备和替换；
- 至少两种明显不同构筑：远程法杖与近战魔剑；
- 三类候选槽位：武器、防具、饰品；
- 固定效果或少量可控词条，四档稀有度；
- 一种主要局外货币；
- 仓库/整备、简单兑换、少量装备选项解锁；
- 不以无限永久属性堆叠作为主要成长路径。

首版不做大型随机词缀池、套装、合成/重铸链、复杂技能树、复杂 NPC 关系或营地自由装修。

## 2. 物品分类与数据字段

### 2.1 物品类别

| 类别 | 功能 | 装备规则 |
|---|---|---|
| 武器 | 决定基础普通攻击行为与武器身份 | 同一时间装备一把；法杖/魔剑构成首版两种武器 |
| 防具 | 提供生存、防御或受击处理方向 | 同一时间装备一件 |
| 饰品 | 提供一个改变战斗行为或资源循环的效果 | 同一时间装备一件 |
| 消耗/资源物 | 用于局内拾取、结算或营地兑换 | 不占装备槽；具体类别依首版内容表确定 |

三类槽位是已确认的首版设计方向。若手机 UI 或内容成本验证显示必须缩减，需在不破坏两种构筑差异的前提下形成明确范围变更，不得在实现中静默删除。

### 2.2 每件装备的最低数据字段

| 字段 | 必需 | 说明 |
|---|---|---|
| item_id | 是 | 稳定唯一标识，不依赖显示名称 |
| display_name | 是 | 玩家可读名称 |
| category | 是 | weapon / armor / accessory / resource |
| slot | 装备类必需 | weapon / armor / accessory |
| rarity | 装备类必需 | common / uncommon / rare / epic |
| short_description | 是 | 简短效果说明 |
| effect_id | 装备类必需 | 指向已定义效果，不直接执行任意文本 |
| effect_parameters | 视效果 | 有类型约束的参数集合 |
| acquisition_source | 是 | 来源/掉落区域/兑换/解锁 |
| stack_rule | 视物品 | 是否可堆叠及堆叠上限 |
| sell_or_exchange_value | 视资源规则 | 如可兑换，记录价值 |
| unlock_requirement | 视解锁物 | 解锁条件 |
| runtime_owner | 运行态 | run_inventory / stash / equipped / consumed |

数据字段只定义产品语义，不指定阶段2前的具体序列化格式、数据库或存档 API。

### 2.3 稀有度表现

四档稀有度：
- 普通（Common）
- 优秀（Uncommon）
- 稀有（Rare）
- 史诗（Epic）

稀有度应同时通过文字、图标/边框形状或其他非颜色信号表达；不得只靠颜色区分。稀有度表达价值与效果强度/复杂度预期，不代表所有高稀有装备都必须是纯数值碾压。

掉率、各档数量和强度预算待后续平衡，不在阶段1冻结。

## 3. 效果设计约束

### 3.1 效果优先级

首版装备效果优先改变战斗行为或选择，例如：
- 法杖弹体的有限穿透、分裂或节奏变化；
- 魔法剑挥砍范围、命中目标数或近战风险回报变化；
- 防具改变受击、防御或护盾行为；
- 饰品改变技能冷却、拾取收益或 Dash/资源循环。

以上为效果方向示例，不表示这些效果都必须进入首版。每个效果必须可读、可测、可在 UI 中简短解释。

### 3.2 数值堆叠边界

- 同类效果叠加必须有明确规则（相加、取最高、乘算或不叠加）；不得由实现者自行决定。
- 首版避免无上限成长；所有乘数/冷却/触发频率应有上限或可验证的软硬边界。
- 装备效果不能绕过已确认的战斗基础规则，例如让基础普攻在没有有效目标时持续攻击空处。
- 装备不得破坏撤离/死亡资产规则。
- 效果应具备可观察反馈，避免只有后台数值变化而玩家无法理解。

## 4. 两种最低构筑规格

### 4.1 远程法杖构筑

核心体验：保持距离、稳定自动选敌、远程输出与安全路线管理。

最低差异证据：
- 法杖远程普通攻击；
- 至少一个可获得的装备效果，强化弹体、射程/节奏或远程输出行为之一；
- 防具/饰品选择可支持远程生存或资源循环；
- 与魔剑构筑相比，玩家更倾向保持距离与选择射击位置。

### 4.2 近战魔剑构筑

核心体验：靠近敌人、利用 120° 扇形挥砍命中多个目标、承担更高位置风险。

最低差异证据：
- 魔法剑近距离 120° 扇形挥砍；
- 至少一个可获得的装备效果，强化挥砍覆盖、近战生存或近身命中回报之一；
- 防具/饰品选择可支持近战承压或近身资源循环；
- 与法杖构筑相比，玩家需要更主动靠近、走位并控制敌人站位。

### 4.3 第三种构筑

技能强化方向作为争取目标，不作为首版最低验收门槛。不得为了凑第三种构筑而削弱法杖与魔剑两种核心差异。

## 5. 局内拾取与背包

### 5.1 拾取行为

- 地面物品应清晰展示类别与稀有度。
- 玩家进入可拾取范围时显示简短提示；触屏交互热区需便于点击。
- 拾取成功后物品进入本局背包（Run Inventory），未撤离前不属于安全仓库资产。
- 背包满时拒绝新拾取，明确提示“背包已满”；不得静默覆盖已有物品。
- 背包容量和堆叠规则待原型/经济平衡确定。

### 5.2 装备与替换

- 玩家可查看物品名称、槽位、稀有度、效果说明及当前装备对比。
- 装备新物品时，同槽位旧装备回到背包（若空间允许）；如无空间，操作必须明确告知并提供可理解的处理路径，不得丢弃旧装备。
- 丢弃、拆解、兑换等不可逆操作必须二次确认，或具备短时间撤销能力。
- 手机界面避免小热区和紧邻的危险操作；确认弹窗不得误触底层战斗操作。
- 局内打开背包时战斗暂停/不暂停的具体产品行为需结合游戏节奏确定；无论采用哪种方式，必须在 UI 明确反馈，且不得出现输入穿透。

## 6. 仓库与营地整备

### 6.1 最小营地闭环

1. 成功撤离后，本局可带出的物品进入仓库/资源账户。
2. 玩家在仓库查看已有装备与资源。
3. 玩家可装备、卸下或替换武器/防具/饰品。
4. 玩家可通过简单兑换获得有限基础装备/补给或解锁装备选项。
5. 玩家确认出战配置并开始下一局。

死亡时不把本局 Run Inventory 自动转入仓库；已存仓库资产与永久解锁按 D-202 保留。

### 6.2 仓库最低行为

- 按类别/槽位查看装备与资源。
- 区分“本局携带”与“仓库已有”资产状态。
- 装备、卸下与替换操作有明确结果反馈。
- 仓库满载/容量上限是否存在，需首版经济/内容量评估；在没有批准容量限制前，不应自行引入仓库满载惩罚。
- 仓库资产不得因新局死亡而丢失。

## 7. 兑换与永久解锁

### 7.1 单一主要货币

- 首版使用一种主要局外货币。
- 货币来源以成功撤离带出的局内资源为主；死亡不带出本局未撤离资源。
- 兑换/解锁消耗必须在确认前显示价格、所得内容和交易结果。
- 不允许出现未说明的隐藏货币或多级材料链。

### 7.2 兑换功能

简单兑换界面至少能让玩家：
- 浏览可兑换的基础装备/补给或装备选项；
- 查看当前货币余额、价格与获得内容；
- 确认兑换；
- 在兑换成功后看到余额和库存变化。

随机商店刷新、每日商店、商人关系、复杂讨价还价不属于首版最低范围。

### 7.3 永久解锁

- 永久解锁主要增加可选装备/效果的选择面。
- 已解锁内容跨局保留，不因死亡回退。
- 不把永久成长设计成无限提高攻击力/生命值的单一路径。
- 解锁条件、价格与解锁内容需在经济表中明确；首版数量保持少量。
- 是否存在失败保底/失败奖励需后续验证，不能在本规格中擅自加入。

## 8. 经济与成长验证

需在后续原型/平衡阶段记录：
- 单局平均拾取价值、成功撤离价值与死亡损失价值；
- 不同风险区域的资源期望与玩家实际进入率；
- 玩家购买基础装备、解锁新选项所需的平均局数；
- 连续失败后玩家是否仍能理解下一步成长路径；
- 玩家是否因永久数值成长而明显降低旧敌人威胁；
- 法杖/魔剑构筑的装备选择是否真实改变战斗行为；
- 背包满载率、物品替换/丢弃误操作率。

不得在没有测试数据前写死掉率、货币产出、兑换价格或解锁局数。

## 9. 首版验收用例

| ID | 场景 | 预期 |
|---|---|---|
| ITEM-01 | 获得法杖/魔剑 | 物品类别、槽位、稀有度和效果说明正确 |
| ITEM-02 | 装备同槽位新物品 | 旧装备不被静默销毁；替换结果清楚 |
| ITEM-03 | 背包满时拾取 | 拒绝拾取并明确反馈 |
| ITEM-04 | 手机打开物品详情 | 文字与操作热区可读、可触达 |
| ITEM-05 | 进行不可逆丢弃/兑换 | 先展示结果并要求确认或提供撤销 |
| ITEM-06 | 获得不同稀有度物品 | 文字/图标等多信号可辨，不仅依赖颜色 |
| BUILD-01 | 使用法杖相关装备 | 远程构筑行为可被观察到改变 |
| BUILD-02 | 使用魔剑相关装备 | 近战构筑行为可被观察到改变 |
| BUILD-03 | 对照两种构筑 | 玩家可描述并实际体验两种构筑的不同战斗选择 |
| CAMP-01 | 成功撤离 | Run Inventory 转入仓库/资源账户一次 |
| CAMP-02 | 死亡 | 未撤离物品丢失，仓库资产/永久解锁/基础出战能力保留 |
| CAMP-03 | 在营地替换装备 | 装备状态与库存状态一致，结果反馈明确 |
| CAMP-04 | 兑换装备/解锁 | 价格、余额、所得内容准确，确认前可退出 |
| CAMP-05 | 开启新局 | 采用当前仓库装备与永久解锁；上局临时状态已清除 |

## 10. 与 D-207 的边界

本规格只定义产品行为与资产状态，不决定 localStorage、IndexedDB、文件导出或其他存档技术。阶段2必须通过 Spike 验证：
- 撤离结算幂等性；
- 仓库与永久解锁写入/读取；
- 刷新/崩溃/版本迁移/异常恢复；
- 存档损坏与备份/重置边界。

在 D-207 结论前，不在设计文档中承诺具体存档实现方式。

## 11. 完成标准

- 三类装备槽位、四档稀有度、物品字段与效果约束明确。
- 法杖与魔剑两种最低构筑具备可观察行为差异。
- 背包满载、替换、不可逆操作与仓库状态规则明确。
- 营地闭环、单一货币、简单兑换与永久解锁行为明确。
- 价格、掉率、容量、物品数量等未验证参数明确留待平衡。
- 本规格完成不等于首版范围冻结、阶段1正式验收或阶段2授权。
