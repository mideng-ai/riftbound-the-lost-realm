# GAME_SCOPE — 首版范围定义

> **版本：** v1.2
> **更新日期：** 2026-11-12
> **状态：** 阶段1（游戏设计，进行中）
> **说明：** 本文档定义首版（第一个可公开发布版本）的范围红线。目的：控制开发范围，避免需求无止境增加。**「可选功能」与「明确不开发」清单为当前整理稿，正式冻结需用户在阶段1结束前确认。**任何新增需求必须先评估是否进入本文档，而不是直接开工。v1.1 为五份基础文档统一修订批次；v1.2 记录阶段0正式验收及阶段1启动，首版 Must-have / Nice-to-have / Out of scope 仍须在阶段1结束前由负责人最终确认，变更摘要见 DECISIONS_LOG.md 变更记录与 DOCUMENT_REVIEW_REPORT.md。

## 1. 首版必须完成的功能（Must-have）

|---|---|---|---|
| 1 | 单局完整流程 | 进入 → 探索搜刮 → 战斗 → 撤离/死亡 → 结算，单局 10–15 分钟 | 全部 |

| 3 | 普通攻击 + 至少一个特殊技能 | 普通攻击和特殊技能的具体操作方式须在阶段1讨论确认，并记录于 DECISIONS_LOG.md（D-201）。确认之前不得将其视为已冻结的开发规则 | 支柱1 |
| 4 | 闪避机制 | 至少一种躲避手段（具体机制待确认后冻结，见 D-204） | 支柱1 |
| 5 | 怪物阵容 | 首版目标数量：4 种普通怪物 + 2 种精英怪物 + 1 个 Boss（**首版目标数量，待阶段1最终确认**），行为差异化 | 支柱1 |

### 1.1 最低可用实现与完整打磨目标

上述 15 项 Must-have 均区分两个层次，防止把打磨量提前当作门槛、也防止把打磨目标偷换成必须项：

- **最低可用实现：** 首版必须具备的基本功能。缺任何一项的最低可用实现，首版视为未完成。
- **完整打磨目标：** 在满足最低要求之后继续提升的质量目标，在阶段5–6 按余量推进，**不属于**首版完成的验收门槛，也不得反向转为可选功能之外的新增必须项。

| # | 功能 | 最低可用实现（首版必须） | 完整打磨目标（满足最低要求后提升） |
|---|---|---|---|
| 1 | 单局完整流程 | 进入→搜刮→战斗→撤离/死亡→结算全流程可跑通，单局 10–15 分钟 | 流程节奏、结算表现与叙事感的精细化 |
| 2 | 移动与基础操作 | 俯视角移动，键鼠与触屏双端可玩 | 手感调校、双端操作舒适度优化 |
| 3 | 普通攻击 + 特殊技能 | 普攻与至少一个特殊技能可用（操作方式待 D-201 确认） | 施法手感、特效与打击反馈打磨 |
| 4 | 闪避机制 | 至少一种躲避手段可用（机制待 D-204 确认） | 闪避手感与无敌帧等参数调校 |
| 5 | 怪物阵容 | 按首版目标数量（4 普 + 2 精英 + 1 Boss，待阶段1确认）完成基本行为 | 行为差异化细节、威胁层次与难度曲线打磨 |
| 6 | 搜刮系统 | 可拾取装备/资源，稀有度可区分 | 稀有度视觉表现、掉落期待感打磨 |
| 7 | 撤离机制 | 撤离点、撤离决策、成功保留战利品 | 撤离仪式感与紧张感的表现强化 |
| 8 | 死亡惩罚 | 按确认后的规则最小实现（规则待 D-202 确认） | 惩罚与留存平衡的数值调校 |
| 9 | 背包与整备界面 | 局内拾取查看 + 局外装备管理可用 | 布局易用性、双端适配体验打磨 |
| 10 | 装备系统 | 至少 2 种明显不同构筑可成立 | 争取 3 种构筑；构筑间平衡与深度打磨 |
| 11 | 营地 | 局外整备 + 基础成长可用（方式待 D-206 确认） | 成长内容与目标感的扩展打磨 |
| 12 | 新手引导 | 新玩家无外部说明可完成首局（形式待 D-209 确认） | 引导文案与触达时机的精细化 |
| 13 | 双端适配 | PC 与手机浏览器均可正常游玩 | 各端性能与舒适度优化 |
| 14 | 基础音频 | 关键反馈音效（施法、命中、拾取、撤离）+ 基础 BGM | 音效覆盖扩展、音画协同与音频打磨 |
| 15 | 存档 | 装备与进度本地持久化（方式待 D-207 确认） | 防丢档策略与数据健壮性增强 |

> 示例（音频）：最低实现只需覆盖施法、命中、拾取、撤离等**关键反馈**音效与基础 BGM；不要求首版一开始就制作大量音效。更丰富的音效库、环境声与音频细节属于完整打磨目标，按阶段5–6 余量推进。

## 2. 首版可选功能（Nice-to-have）

以下功能 **默认不做**。仅在首版必须项全部完成、时间与质量有余量的前提下，经用户逐项批准后加入。每个候选都必须先过「四大支柱检验」。

| 候选功能 | 服务支柱 | 备注 |
|---|---|---|
| 更多地图/主题场景 | 支柱2、3 | 第二张地图或地图变体 |
| 更多 Boss | 支柱1 | 复用已有 Boss 框架时成本较低 |
| 简单任务/挑战系统 | 短期目标 | 局内小目标结构化 |
| 成就系统 | 长期目标 | 纯记录性质，不做奖励联动也可 |
| 游戏手柄支持 | 支柱1 | 仅 PC 端 |
| 简单设置面板（音量、画质） | 体验 | 成本低，可视情况提前 |
| 统计页面（局数、击杀、最高纪录） | 长期目标 | 数据已有，仅做展示 |

规则：
- 可选项 **不得** 挤占必须项的完成度与打磨时间。
- 每加入一个可选项，需在 DECISIONS_LOG.md 记录批准时间与理由。

## 3. 首版明确不开发的功能（Out of scope）

以下内容明确排除在首版之外。除非用户明确提出并更新本文档，否则任何阶段都不得顺手实现。列出排除项本身即是一种决策，具体条目为当前整理稿，供用户确认：

| 排除项 | 理由 |
|---|---|
| 多人模式 / 联机 | 项目定位为单人 PvE；联机会带来数量级的架构复杂度 |
| PvP 玩法 | 与单人 PvE 定位冲突 |
| 剧情对话 / 过场动画系统 | 世界观保持轻量，首版以玩法表达 |
| 开放世界 / 大世界探索 | 单局 10–15 分钟的搜打撤结构与开放世界不匹配 |
| 内购 / 广告 / 商业化系统 | 商业模式 **待确认**，首版不做任何商业化 |
| 账号系统 / 云存档 / 跨设备同步 | 首版用本地存档；涉及后端与隐私，成本高 |
| i18n 多语言 | 英语首发；架构上允许后续扩展，但首版不做其他语言 |
| 玩法 MOD / 编辑器 | 超出首版目标 |
| 宠物 / 随从系统 | 未在四大支柱中，属新增玩法，需单独评估 |
| 天气 / 昼夜系统 | 表现层增强，非核心循环必需 |
| 原生 App（打包上架应用商店） | 首发平台限定浏览器 |

## 4. 范围控制规则

1. **新需求入口唯一：** 任何新功能想法先记入 DECISIONS_LOG.md（待确认），经用户批准后归入本文档三类之一，再进入开发。
2. **支柱检验：** 无法说明服务于哪个支柱的功能，默认进入「不开发」。
3. **必须项优先：** 必须项未全部验收前，不启动任何可选项。
4. **范围冻结点：** 建议在阶段1结束时冻结必须项清单；此后修改必须项需用户明确批准并评估对路线图的影响。
5. **减法优先：** 与其临时加功能，不如把已有功能做爽。宁可少做功能，也要保证核心玩法真正有趣、运行稳定。
