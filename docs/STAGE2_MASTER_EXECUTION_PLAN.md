## 2. 已知基线与限制

- 技术方向固定：Babylon.js + TypeScript + Vite（D-007），不得擅自换引擎/框架。
- 平台目标：PC 浏览器与手机浏览器；手机优先但不取消 PC。
- 首版范围冻结：15 Must-have、7 类 Nice-to-have、11 类 Out of scope。阶段2不实现完整玩法或扩张范围。
- ST2-001 WebGL2 证据仅来自 Linux Firefox/llvmpipe 软件渲染，不代表 Mac 真 GPU 或手机真机。
- ST2-002 证明受控条件下 NodeMaterial 与 GLSL cel shader 可实现等价基础着色，但未选定最终渲染管线。
- Mac mini 已知基线（需执行时重新核对）：Apple M1、8GB、macOS 15.0.1、Node 24.16.0、npm 11.13.0、Git 2.39.5。
- 手机真机型号、系统、浏览器尚未建立经负责人核验的矩阵。不得推测或伪造真机结果。

## 3. S2-C：法术特效 Spike

目标：验证阶段3可复用的最小技术路径，不制作正式首版技能。

必须完成：
1. 隔离 Spike 中建立基础法术投射物生命周期：发射、飞行、消失/命中。
2. 建立命中反馈：闪光、粒子或适合 Babylon.js 的替代方案。
3. 比较轻量与较丰富方案，记录可读性、复杂度、粒子/对象数量、透明层和过度绘制风险。
4. 记录资源释放、对象复用/池化是否必要及其证据，不引入无证据的复杂系统。
5. 在可用浏览器运行并记录环境、构建、截图、日志、复现步骤和限制。
6. 提交推荐技术路径及其适用边界。

不在范围：正式技能机制、伤害、冷却、资源消耗、技能 UI、正式音频/素材集成。优先程序化占位特效；引入任何具体音频资产前必须完成许可证核查。

## 4. S2-D：PC/手机统一输入抽象

目标：建立平台无关输入层，游戏逻辑不直接读取 DOM 键盘、鼠标或触控事件。

必须完成：
1. 定义清晰的 typed input actions/states，例如移动向量、普通攻击意图、技能动作、闪避动作、暂停/焦点状态。
2. 键鼠与触屏适配器分离；游戏逻辑只消费统一接口。
3. 处理持续/瞬时输入、按下/释放、触摸取消、窗口失焦、页面隐藏、指针锁丢失。
4. 多点触控区分移动区与技能/按钮区，避免手指跨区误触。
5. 提供可运行演示、自动化/手动测试清单、接口文档。
6. 桌面浏览器验证键鼠；准备手机真机测试页、访问步骤和逐项记录表。
7. WorkBuddy 无法实际访问手机时，必须标记 OWNER_DEVICE_TEST_REQUIRED；桌面模拟、DevTools 模拟不算真机通过。

不在范围：完整 HUD、技能系统、战斗或正式控制 UI。不得改变已确认的玩法输入规则。

## 5. S2-E：D-207 本地存档技术比较

必须比较 localStorage 与 IndexedDB，覆盖：
- 同步/异步模型、数据结构与数据量适配；
- 原子性/事务、写入失败与中断；
- schema 版本迁移、兼容与回滚；
- 数据损坏、部分写入与恢复；
- 配额、浏览器清理、隐私模式/存储限制；
- PC/手机主流浏览器支持差异；
- 导出/重置和用户数据边界；
- 实现复杂度、测试成本和阶段3使用方式。

最小验证：版本化数据读写、旧版本迁移、损坏数据恢复、失败/配额处理，并在可用 PC/手机环境测试。交付比较表、源码/日志、浏览器矩阵、建议 schema、迁移策略和明确推荐。

**D-207 决策门：** WorkBuddy 只能提交建议，不得自行把 localStorage 或 IndexedDB 标为已确定。负责人确认后才更新 DECISIONS_LOG.md 并落地正式 adapter。确认前只允许定义接口与 mock/in-memory adapter。

## 6. S2-F：D-210 性能测量与预算建议

必须建立可复现基准场景：相机、环境、角色占位物、法术特效、不同数量的简单实体/粒子；不得实现正式敌人或玩法。

记录：
1. 冷启动/首次加载、资源加载、稳定运行帧时间（优先 p50/p95）、FPS、内存（可测时）、长时间运行和场景切换观察。
2. 负载阶梯与压力点，指出帧时间恶化、内存增长或卡顿出现条件。
3. 环境逐项记录：设备、OS、浏览器、GPU/渲染后端、分辨率、电源状态、测试时长。
4. WorkBuddy Linux 沙箱、负责人 Mac M1 真 GPU、真实手机结果分栏记录，不得混算。
5. 给出分设备类别预算建议、误差、未测设备和风险；实测结果与建议目标分开。

**D-210 决策门：** 不得把候选 FPS、加载时间或内存阈值写成已确定指标。负责人确认后才更新 DECISIONS_LOG.md 和正式预算文档。没有真实设备证据的类别标为待测，不得推算为通过。
