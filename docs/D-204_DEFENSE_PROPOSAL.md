# D-204_DEFENSE_PROPOSAL — 闪避与防御机制提案

> 版本：v0.1  
> 日期：2026-11-12  
> 状态：AI 推荐提案，等待项目负责人审查；不构成已确认规则

## 1. 推荐方向

推荐首版只提供一种主动闪避动作：短距离 Dash；不额外加入格挡、招架或翻滚系统。

理由：
- 为玩家提供主动应对近战冲锋和范围预警的手段。
- 操作成本低于多套防御按键。
- 可同时映射到触屏按钮与 PC 键盘。
- 与敌人清晰的攻击预警形成「看见危险—选择时机—改变位置」的可学习循环。

## 2. 输入建议

- 手机：右侧独立 Dash 按钮，与两个特殊技能按钮明显区分。
- PC：暂定 Space。
- Dash 按钮只负责一次闪避，不承担攻击或技能功能。
- 触屏按钮需要明显冷却反馈，避免玩家误以为输入失灵。

## 3. 方向规则建议

- 有移动摇杆输入时，Dash 沿当前移动方向。
- 无移动输入时，沿角色当前朝向；若当前朝向无效，则不自动朝敌人冲去。
- Dash 不允许穿过实体墙壁或不可通行地形。
- Dash 可穿过普通敌人的碰撞体与否，作为原型测试项，不先写死。

## 4. 无敌帧与伤害规则

不直接冻结长无敌帧。

建议在 M1 原型中对比两种方案：
- A：Dash 期间没有无敌帧，完全依靠位移躲开攻击判定。
- B：Dash 起始短时间具有极短无敌窗口，窗口必须明显短于整个 Dash。

比较指标：
- 玩家能否理解何时成功躲避。
- 触屏操作是否能及时响应。
- Dash 是否让敌人攻击失去威胁。
- 高延迟/低帧率下是否出现不公平命中。

若 B 方案显著改善公平感，再调试无敌窗口；不预设具体毫秒值。

## 5. 冷却与资源

- 推荐 Dash 使用冷却，不消耗与技能共用的魔法资源。
- 冷却时间、位移距离、动作时长均留待原型验证。
- 不建议首版加入多层充能、耐力条或 Dash 连段。
- 冷却中按钮应显示进度或灰态，并有清晰的不可用反馈。

## 6. 反制与敌人配合

- 敌人冲锋、重击、地面范围攻击必须有足够清晰的预警。
- Dash 不应成为规避所有机制的万能解；部分攻击可通过离开危险区域或提前走位规避。
- Boss 与精英攻击应给玩家可识别的反应窗口。
- 受击后是否存在硬直/短暂无敌，与 Dash 无敌帧分开设计，避免多套保护叠加。
