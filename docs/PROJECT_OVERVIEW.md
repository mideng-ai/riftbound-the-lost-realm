## 1. 游戏定位

- **类型：** 3D 俯视角单人 PvE 魔法搜打撤游戏（Extraction / Loot 动作游戏）。
- **平台：** 电脑和手机浏览器（Web 优先，无需下载安装）。
- **首发语言：** 英语。
- **单局目标时长：** 10–15 分钟。
- **玩家形态：** 单人游玩，无多人、无 PvP。
- **核心卖点：** 在一局之内完成「进入 → 搜刮 → 战斗 → 决策撤离」的完整紧张循环，并通过跨局的装备成长获得长期目标感。

## 2. 世界观

- **主题：** 魔法奇幻，围绕一个「失落的领域（The Lost Realm）」展开。
- **基调：** 鲜艳、明快的卡通奇幻，紧张感来自玩法（风险与撤离决策），而非黑暗压抑的美术氛围。
- **当前状态：** 世界观细节（世界为何失落、玩家角色身份、营地设定等）尚未正式确定，属于 **待确认** 事项。详细设定将在阶段1（游戏设计）中完成并记录于设计文档。

## 3. 核心玩法循环

游戏由四个支柱支撑，任何新功能都必须说明它服务于哪一支柱：

1. **有爽感的魔法战斗** — 施法打击感、命中反馈、技能组合。
2. **有价值的探索和搜刮** — 探索地图、发现并收集装备与资源。
3. **紧张刺激的撤离决策** — 继续搜刮还是带战利品撤离？贪婪与安全的权衡。
4. **有意义的装备成长** — 跨局积累装备，装备组合带来玩法变化。

**单局循环（约 10–15 分钟）：**

```
进入地图 → 探索 / 搜刮 → 遭遇怪物 → 战斗 → 资源变多/风险变高
   → 决策：继续深入 or 前往撤离点 → 撤离成功：保留战利品 / 死亡：受到惩罚
        → 回到营地整备 → 携带更好装备开始下一局
```

**跨局循环：** 撤离所得装备与资源 → 强化角色与装备 → 解锁更深、更难、回报更高的内容 → 更高风险与奖励。

## 4. 美术方向

- **风格：** 精致、鲜艳、卡通化的 3D 魔法奇幻风格。
- **渲染：** 卡通渲染方向，强调色彩饱和、轮廓清晰、法术特效醒目。
- **可读性优先：** 敌人、法术、拾取物必须在俯视角下清晰可辨（详见 GAME_DESIGN_PRINCIPLES.md「UI 与可读性」）。
- **具体美术规格（模型面数、贴图尺寸、配色板等）**：**待确认**，将在阶段1–2 中根据性能预算确定。

## 5. 首版内容

首版（可发布的最小完整体验）目标包含：

- 一张可重复游玩的对局地图（生成方式 **待确认**，见 DECISIONS_LOG.md）。
- 一套基础法术/技能：普通攻击 + 至少一个特殊技能（操作方式 **待确认**）。
- 若干怪物类型与至少一个 Boss。首版目标数量：**4 种普通怪物 + 2 种精英怪物 + 1 个 Boss（首版目标数量，待阶段1最终确认）**；具体设计同样待阶段1确认。
- 搜刮系统：可拾取的装备与资源。
- 撤离机制与死亡惩罚（规则 **待确认**）。
- 装备系统与背包/整备界面（组合方式 **待确认**）。
- 营地作为局外整备与成长场所（成长方式 **待确认**）。
- 基础新手引导（引导形式 **待确认**）。
- 支持 PC（键鼠）与手机（触屏）双端操作（具体方案 **待确认**）。

首版范围的红线见 GAME_SCOPE.md。

## 6. 技术方向

**技术方向（当前选定，待阶段2技术验证）：**

| 层 | 选型 | 用途 |
|---|---|---|
| 渲染引擎 | Babylon.js | 3D 渲染、输入、音频等引擎能力 |
| 语言 | TypeScript | 全部游戏代码 |
| 构建 | Vite | 开发服务器与打包 |
| 平台 | Web 浏览器（PC + 手机） | 首发目标 |

> 上表为当前选定的技术方向，**尚未经过技术验证**；正式工程实施前仍需在阶段2通过技术验证（见 DEVELOPMENT_ROADMAP.md 阶段2）。未经项目负责人批准，不得擅自更换技术栈。

- 优先研究成熟开源项目与免费工具；引入任何第三方资源前必须核查许可证。
- 代码原则：简单、模块化、易维护；不擅自改变已确定的技术架构。
- 性能目标（帧率、机型覆盖等具体指标）：**待确认**，将在阶段2（技术基础）制定。

## 7. 项目开发原则

1. **支柱检验：** 所有新功能必须说明如何服务于四大支柱，否则不进入范围。
2. **阶段推进：** 严格按 DEVELOPMENT_ROADMAP.md 八阶段路线推进，不跳阶段、不并行大开大合。
3. **范围控制：** 首版范围以 GAME_SCOPE.md 为准，避免需求无止境增长。
4. **决策留痕：** 设计决策记录于 DECISIONS_LOG.md，区分「已确定 / 暂定 / 待确认」；重要决策由用户拍板。
5. **可验收：** 每项工作有明确验收标准；不得虚报测试结果，不得虚构运行结果。
6. **少而精：** 宁可少做功能，也要保证核心玩法真正有趣、运行稳定、容易维护。
7. **资源合规：** 第三方代码/模型/贴图/音频/字体使用前必须检查许可证与商用限制，不得复制受版权保护的商业游戏资产。
8. **移动端同级：** 手机浏览器是首发平台之一，任何玩法与 UI 设计必须同时考虑触屏体验。

## 8. 首个技术里程碑

**里程碑 M1：可玩原型（对应阶段3完成）**

> **M1 是阶段3的可玩原型，不等于首版完整发布版本。** 首版发布版本需完成 GAME_SCOPE.md 中最终冻结的全部 Must-have 内容（详见 GAME_SCOPE.md）。不得把首版的全部怪物、技能、装备、营地成长、完整音频和打磨工作提前塞入 M1。

M1 主要验证以下内容（在一个普通浏览器（PC Chrome）中可运行的单局垂直切片）：

- 玩家俯视角移动。
- 普通攻击和至少一个特殊技能。
- 至少一种可追击玩家的怪物。
- 怪物死亡反馈和击杀奖励。
- 基础战利品拾取。
- 基础背包查看。
- 撤离点和撤离成功。
- 死亡惩罚的最小实现。
- 一个可以完整运行的单局垂直切片：局面稳定运行、无崩溃级 Bug，帧率表现符合阶段2制定的目标（目标值 **待确认**）。

M1 达成意味着四大支柱各有一个最小可验证的实现，之后才进入核心玩法深化（阶段4，边界定义见 DEVELOPMENT_ROADMAP.md）。
