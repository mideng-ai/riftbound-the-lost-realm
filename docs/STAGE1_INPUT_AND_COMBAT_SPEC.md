# STAGE1_INPUT_AND_COMBAT_SPEC — 双端输入与战斗交互规格

> **版本：** v1.0  
> **日期：** 2026-11-12  
> **状态：** 已确认设计方向的开发规格；布局尺寸与战斗数值须经原型测试  
> **适用范围：** 首版输入/战斗系统；手机优先，PC 浏览器适配  
> **依据：** GAME_SCOPE.md v1.4、GAME_DESIGN_SPEC.md v2.1、STAGE1_CONFIRMED_DESIGN_BASELINE.md v1.0、DECISIONS_LOG.md v4.6  
> **决策：** D-201、D-204 已确认；本文件将确认方向转为交互行为和验收规则，不新增玩法决策。

## 1. 范围与不可变规则

### 1.1 首版必须支持

- 一名可操作角色。
- 两种武器：远程魔法法杖、近战魔法剑。
- 两种特殊技能，均由玩家手动施放。
- 普通攻击自动触发、自动选敌；无有效目标时停止攻击。
- 手机横屏优先；左手移动，右侧提供技能和 Dash 操作。
- PC 使用键盘移动与技能键；鼠标不承担普通攻击瞄准。
- 允许移动中持续普通攻击。
- Dash 为首版唯一主动闪避动作，不额外加入格挡/招架系统。

### 1.2 不在首版实现

- 自动施放特殊技能、自动/手动模式切换 UI。
- 鼠标手动指定普通攻击目标。
- 独立格挡、招架、翻滚、Dash 连段或耐力系统。
- 复杂的技能轮盘、技能组合编辑器或可配置键位系统（除非后续可用性测试证明必要）。

## 2. 输入映射

| 行为 | 手机浏览器（横屏） | PC 浏览器 | 规则 |
|---|---|---|---|
| 移动 | 左下虚拟摇杆 | WASD | 归一化移动向量；斜向移动不得快于直线 |
| 普通攻击 | 自动 | 自动 | 系统选敌并触发；无有效目标停火 |
| 特殊技能1 | 右侧按钮1 | Q | 手动施放 |
| 特殊技能2 | 右侧按钮2 | E | 手动施放 |
| Dash | 右侧独立按钮 | Space | 独立冷却，不消耗技能共用魔法资源 |
| 暂停/设置 | HUD 独立入口 | HUD 独立入口；Esc 可作为辅助快捷键 | 不与战斗输入复用 |
| UI 操作 | 触控 | 鼠标/键盘 | UI 输入不得误触发战斗动作 |

### 2.1 手机布局约束

1. 默认以横屏作为首版目标方向；竖屏不作为首版核心操作验收模式。
2. 左下虚拟摇杆与右侧技能/Dash 区域分离，保证移动与动作可以同时输入。
3. 两个技能按钮与 Dash 按钮必须在形状、图标、冷却反馈上可区分；不得仅靠颜色区分。
4. 触控热区避开系统手势边缘、刘海/圆角安全区与浏览器 UI 遮挡区域。
5. HUD 不得覆盖角色周围关键危险预警、撤离交互目标或主要战斗区域。
6. 页面失去焦点、浏览器切后台或触控取消时，必须清除残留移动输入，避免角色持续移动。
7. 多点触控必须支持：左手持续移动的同时，右手点击技能或 Dash；一个手指抬起不得错误取消另一个手指的输入。

**待测而非冻结：** 摇杆直径、按钮直径、按钮间距、屏幕边距、透明度与 HUD 具体位置。通过目标手机触控测试确定。

### 2.2 PC 输入约束

1. WASD 输入与手机摇杆映射到同一归一化移动行为。
2. Q/E 按下时各触发一次技能请求；按住不得重复施放，除非某技能本身明确设计为持续通道（首版默认不采用）。
3. Space 按下时触发一次 Dash 请求；按住不得自动连发。
4. 浏览器窗口失焦、标签页隐藏或键盘焦点转移时，清除所有按键状态。
5. 输入焦点位于文本框、按钮等 UI 控件时，不得把 WASD/Q/E/Space 同时解释为游戏动作。
6. 不依赖鼠标点击/拖动进行普通攻击或目标指定。

## 3. 移动与朝向

- 输入方向先归一化，再转换为世界移动方向；斜向移动速度与直线移动速度上限一致。
- 无移动输入时角色停止移动，不自动向敌人移动。
- 角色朝向由最近一次有效移动方向更新；若技能或攻击需要朝向，则使用动作开始时锁定的朝向/目标方向。
- 自动选敌不应强制角色追逐敌人；角色移动由玩家输入决定。
- 移动中允许普通攻击继续进行，不因移动输入而暂停攻击循环。
- 输入向量短暂抖动或摇杆回中时应有合理死区，避免角色原地微动；死区阈值通过设备测试确定。

## 4. 自动普通攻击状态规则

### 4.1 通用状态机

| 状态 | 进入条件 | 行为 | 退出条件 |
|---|---|---|---|
| Idle | 无有效目标，或武器暂不可攻击 | 不生成攻击；保留移动控制 | 出现有效目标且武器可攻击 |
| AcquireTarget | 需要首次选敌或当前目标失效 | 按第5节优先级评估候选目标 | 选到目标→Windup；无目标→Idle |
| Windup | 已选目标且攻击动作开始 | 锁定本次攻击方向/目标快照；播放前摇（如有） | 前摇结束→Resolve |
| Resolve | 到达攻击判定时点 | 生成弹体或执行挥砍判定；本次攻击不因轻微距离变化中途改向 | 判定/发射完成→Recovery |
| Recovery | 本次攻击执行完成 | 播放后摇/等待攻击间隔；仍可移动 | 攻击间隔结束→重新评估目标 |
| Disabled | 角色死亡、结算、受控或场景不允许战斗 | 停止新攻击并清理无效状态 | 返回可战斗状态后重新 AcquireTarget |

### 4.2 当前攻击不可被轻微变化打断

- 一次攻击动作开始后，攻击目标/方向按动作开始时的有效状态锁定。
- 法杖弹体生成后沿发射方向飞行，不在空中瞬间追踪新目标；追踪弹属于未来特殊武器效果，不属于基础攻击。
- 魔法剑一次挥砍的方向与判定扇形在该次动作期间保持一致；不得因目标切换导致命中扇形瞬间转向。
- 若角色死亡、场景切换或攻击被明确的控制效果打断，可终止当前动作。
- 当前目标在攻击过程中死亡/失效，不回滚已发出的弹体或已开始的挥砍；下一次攻击周期重新选敌。

### 4.3 两种武器基础攻击

**魔法法杖**
- 远程单目标导向的基础攻击。
- 攻击开始时选定目标并锁定发射方向。
- 弹体生成后按既定方向飞行；目标移动后允许自然躲开。
- 基础弹体不自动追踪，不穿透多个敌人，除非后续明确设计为装备/技能效果。
- 攻击间隔、射程、弹速、弹体尺寸和伤害均待原型验证。

**魔法剑**
- 近距离扇形挥砍，已确认扇形角度为 120°，中等攻击距离。
- 标准挥砍节奏的初始目标约每 1 秒一次。
- 攻击开始时锁定朝向；本次挥砍判定在角色前方扇形区域内，可命中范围内多个有效敌人。
- 120° 与约 1 秒是已选定的初始设计目标，但仍需原型验证；中等距离须在原型中确定世界单位。
- 挥砍判定应与动画时序一致，避免视觉已挥过但判定尚未发生或反之。

## 5. 自动选敌规则

### 5.1 候选有效性

候选敌人必须同时满足：
- 存活且可被攻击；
- 位于当前武器允许的有效攻击范围/选敌范围；
- 不处于无敌、不可选中或已离场状态；
- 目标属于当前遭遇允许攻击的敌对单位。

视线/遮挡规则需与地图碰撞和弹体规则一致；阶段1确定行为边界，具体遮挡检测方式留阶段2/3实现验证。

### 5.2 选择优先级

1. **即时威胁：** 正在攻击、冲锋、施放危险技能，或已贴近并对玩家形成直接压力的敌人。
2. **高价值威胁：** 在合理距离内的精英、Boss、远程/支援单位。
3. **普通威胁：** 其他有效普通敌人，优先较近目标。

距离是同层级候选目标的辅助排序条件，不得让远处精英无条件压过正在贴身攻击玩家的普通敌人。

### 5.3 目标保持与切换

- 当前目标仍有效且没有出现明显更高优先级威胁时，尽量保持当前目标，减少目标抖动。
- 当前目标死亡、失效、超出有效范围、不可攻击或被遮挡（若遮挡规则判定无效）时，重新选敌。
- 出现明显更高优先级威胁时，可在下一次攻击动作开始前切换。
- 当前攻击动作/弹体已开始时不追溯改变方向；切换只影响后续攻击。
- 没有任何有效目标时停止普通攻击，不向空处持续发射。

### 5.4 参数验证项

- 各武器的有效选敌范围与攻击范围关系；
- 即时威胁判定条件及威胁类别；
- 同级目标距离权重；
- 目标保持时间/切换阈值；
- 视线遮挡、墙体阻挡和弹体碰撞；
- 多目标聚集时的目标稳定性与玩家可理解性。

## 6. 技能施放规则

- 两种特殊技能均由玩家手动触发；首版不包含自动施法或自动/手动模式 UI。
- 手机点击技能按钮、PC 按下对应 Q/E 键时提交一次施放请求。
- 技能默认点击即施放；只有效果确实需要方向或落点时，才针对该技能使用按住拖动瞄准。
- 技能施放前检查：角色可行动、技能已解锁/装备、冷却完成、资源足够、目标/位置条件满足。
- 条件不满足时不消耗资源、不进入技能效果，并显示明确的不可用反馈（冷却、资源不足、状态受限或目标无效）。
- 技能请求成功后，按技能自身定义处理消耗与冷却；不得因重复触控或按键抖动在一次输入中多次施放。
- 技能能否移动中施放由具体技能行为决定；除非技能描述要求锁定/蓄力，不应无理由冻结移动。
- 技能按钮按下、成功施放、冷却中、资源不足、受控不可施放等状态必须有可辨识反馈。
- 设备振动仅为可选增强，不得作为施放成功的唯一反馈。

## 7. Dash 规则

- Dash 是首版唯一主动闪避动作。
- 手机通过独立 Dash 按钮触发；PC 通过 Space 触发。
- 有有效移动输入时沿移动方向 Dash；无移动输入时沿角色当前朝向。
- Dash 不穿越墙体或不可通行地形；遇到障碍时按碰撞结果停止/滑动，不得穿墙。
- Dash 使用独立冷却，不消耗技能共用魔法资源。
- 冷却中、角色死亡/结算、受控或其他不允许动作的状态下不能触发。
- 一次按键/点击只触发一次 Dash，不支持按住连发。
- Dash 距离、持续时间、冷却、加速度曲线、是否穿过普通敌人碰撞体、是否存在起始短无敌窗口均为 M1 A/B 测试参数，不在此处冻结。
- 无敌帧 A/B：A 为全程无无敌帧，仅依靠位移；B 为 Dash 起始短窗口无敌。对比公平感、可读性、低帧率/延迟下命中一致性及对敌人威胁的削弱程度。

## 8. 输入优先级与冲突

同一帧收到多个动作请求时：
1. 角色死亡/场景结束等禁用状态优先，清除战斗输入。
2. Dash 与技能分别独立请求；两者同帧冲突时不得意外双重触发。默认先接受先到的有效动作请求，具体技能是否允许与 Dash 同时执行由技能定义，但首版默认互斥。
3. 普通攻击自动循环不应阻塞移动、技能或 Dash 输入。
4. 移动持续输入与技能/Dash 按钮必须支持多点触控并行。
5. UI 点击不得穿透到游戏场景触发攻击、Dash 或拾取。
6. 暂停、弹窗、结算等 UI 模态打开时，游戏动作输入被屏蔽；关闭后清除残留按键/触控状态。

## 9. 失败与异常处理

- 页面失焦/切后台：清空移动、技能按住态和 Dash 输入；恢复后不得自动补发已错过动作。
- 触控取消/手指离屏：清除对应触点，不得卡住摇杆或按钮。
- 多指触控：按触点 ID 独立管理，不因单个触点结束而重置其他触点。
- 重复按键事件：通过按下沿/输入请求去重，防止技能或 Dash 连发。
- UI 遮挡：任何弹窗出现时暂停战斗输入，避免底层操作穿透。
- 角色死亡或撤离成功：停止自动攻击、取消未执行技能请求并清除移动输入。

## 10. 验收用例

| ID | 前置/操作 | 预期结果 |
|---|---|---|
| INPUT-01 | 手机横屏进入战斗，左手拖动摇杆 | 角色按输入方向移动，斜向速度不超过直线速度 |
| INPUT-02 | 手机持续移动时，右手点击技能按钮 | 移动持续；技能仅触发一次 |
| INPUT-03 | 手机持续移动时，右手点击 Dash | 移动/Dash 按确认规则执行，无触点互相取消 |
| INPUT-04 | PC 按 WASD 组合键 | 移动方向与手机输入一致，斜向不加速 |
| INPUT-05 | PC 按 Q/E | 对应技能各触发一次；按住不重复触发 |
| INPUT-06 | PC 按 Space | 仅触发一次 Dash；冷却中再次按下无效果且有反馈 |
| COMBAT-01 | 攻击范围内无有效敌人 | 普通攻击停止，不向空处持续攻击 |
| COMBAT-02 | 出现即时威胁与更远精英 | 自动攻击优先即时威胁 |
| COMBAT-03 | 当前目标有效且同级新目标靠近 | 保持当前目标，除非新目标构成明显更高优先级威胁 |
| COMBAT-04 | 当前目标死亡/离开有效范围 | 当前攻击按动作锁定规则结束，下一次攻击重新选敌 |
| COMBAT-05 | 移动中存在有效目标 | 普通攻击继续循环，不要求玩家停止移动 |
| COMBAT-06 | 法杖弹体发射后目标移动 | 弹体沿已锁定方向飞行，不瞬间追踪 |
| COMBAT-07 | 魔法剑挥砍时目标变化 | 当前挥砍方向与 120° 判定扇形保持一致 |
| SKILL-01 | 技能冷却中点击/按键 | 不施放、不扣资源，显示冷却反馈 |
| SKILL-02 | 资源不足时施放技能 | 不施放、不扣资源，显示资源不足反馈 |
| SKILL-03 | 技能有效时快速重复点击/按键 | 单次输入不产生重复施放 |
| DASH-01 | 有移动输入时触发 Dash | 沿当前移动方向位移 |
| DASH-02 | 无移动输入时触发 Dash | 沿角色当前朝向位移 |
| DASH-03 | Dash 路径遇到墙体 | 不穿墙 |
| DASH-04 | Dash 冷却中再次触发 | 不执行 Dash，显示冷却状态 |
| INPUT-07 | 页面失焦、触控取消或弹窗打开 | 输入状态清空；无残留移动/动作或 UI 穿透 |

## 11. M1 原型验证计划

M1 不要求一次实现全部首版内容，但应为上述规则提供最小验证样本：

1. 至少一种武器普通攻击与至少一个手动技能可运行。
2. 手机优先验证：左摇杆 + 技能按钮 + Dash 的多点触控并行。
3. 同一场景放置普通敌人与至少一种即时威胁行为，验证选敌优先级与目标稳定性。
4. 通过录屏观察移动中攻击、法杖发射锁定/魔法剑挥砍方向锁定。
5. 对 Dash 无敌帧与敌人碰撞交互进行 A/B 测试；保留原始测试记录。
6. PC 键位映射在阶段2/3按同一输入行为接口验证，不改变手机优先顺序。

## 12. 规格完成标准

- 双端输入映射无冲突，且与已确认设计基线一致。
- 自动攻击、目标优先级、目标保持、动作锁定与无目标停火均有明确行为规则。
- 技能与 Dash 的成功/失败输入反馈、冷却/资源规则明确。
- 多点触控、窗口失焦、UI 模态、死亡/结算等边界情况有验收用例。
- 所有未冻结参数已进入原型验证计划，不伪装成最终数值。
- 本规格完成不代表阶段1正式验收、GAME_SCOPE 最终冻结或阶段2开工授权。
