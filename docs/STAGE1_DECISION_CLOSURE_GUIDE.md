## 0. 如何审查（先看这里）

每组只需给出一个明确结果：**批准 AI 推荐**、**按列出的替代方案修改**，或**暂缓并说明允许延期到哪个阶段及其影响**。可以整组批准，也可以只批准其中部分条目；未明确提及的条目继续保持「待确认」。

- 「批准 AI 推荐」只对该组中标注为推荐的规则生效；测试参数仍保持测试起点，不会自动冻结。
- 「暂缓」必须说明是否允许阶段1带着该未决项申请验收，以及对应风险由谁接受。
- 负责人此前的「材料已阅」不等于批准；本指南发布也不改变 DECISIONS_LOG 的任何决策状态。
- D-207 存档技术方案与 D-210 性能预算仍留阶段2技术 Spike，不在本次决策包内。

## 1. 第一组：操作与战斗 — D-201 + D-204

**需要解决的问题：** 手机和 PC 如何操作；玩家如何主动躲避危险；技能与闪避是否争抢触控空间。

### 现状与已确定边界
- 已确定：手机左手移动；双端普通攻击自动触发并自动判断方向；无有效目标时停火；附近威胁优先、距离辅助；首版特殊技能手动施放。
- 已确定：法杖远程普通攻击；魔法剑 120° 扇形、中等距离、标准挥砍约每秒一次为初始目标（仍需原型验证）。
- 尚未确定：手机横屏、摇杆与按钮布局、技能交互、PC 键位、移动中普攻、Dash 是否存在及其机制。

### AI 推荐默认方案（待批准）
**D-201 输入**
1. 手机首版以横屏为主：左下虚拟摇杆；右下两个独立技能按钮；普通攻击无专用按钮；HUD 避开安全区。
2. 两种首版技能默认点击即施放。范围技能优先以角色为中心；防御/位移技能即时触发。只有技能效果确实需要方向或落点时，才单独采用按住拖动瞄准。
3. PC 使用 WASD 移动、Q/E 施放两个技能；鼠标负责 UI，不负责手动指定普通攻击目标。
4. 推荐允许移动中持续普通攻击；一次攻击/挥砍/弹体开始后保持该次动作一致，当前攻击结束后再按已确认选敌原则重新评估目标。

**D-204 防御**
1. 首版采用单一 Dash，不增加独立格挡、招架或复杂防御系统。
2. 手机增加独立 Dash 按钮；PC 暂定 Space。方向优先沿当前移动输入，无移动输入时沿角色当前朝向。
3. Dash 不穿墙；是否穿过普通敌人碰撞体留待原型验证。
4. Dash 使用独立冷却，不消耗技能共用魔法资源。
5. 无敌帧不在文档阶段直接冻结；M1 对比「纯位移」与「起始极短无敌窗口」，依据公平感与实测决定。

### 可选替代方案
- 输入：PC 改为方向键或其他键位；技能采用按住瞄准；手机采用非横屏布局。若选这些方案，需同步检查双端 UI 与触达性。
- 普攻：不允许移动中攻击，或允许移动但降低攻击效率；须明确其对法杖与魔法剑是否一致。
- 防御：不设 Dash、仅靠走位；或加入 Dash + 护盾。后者会增加手机按钮和技能平衡成本。

### 影响范围
FR-MH-02/03/04/13；M1 的移动、普攻、技能与防御输入；首版手机 HUD 和 PC 键位；D-201 与 D-204 必须联合冻结，避免重复占用按键。

### 留给原型验证的数值/行为
攻击间隔、法杖射程/弹速、魔法剑距离/判定窗口、选敌距离与切换阈值、Dash 距离/时长/冷却、无敌窗口、触控按钮尺寸与误触率。不得把这些测试起点写成已确认数值。

## 2. 第二组：地图、撤离与死亡 — D-202 + D-203

**需要解决的问题：** 玩家在怎样的地图上探索、如何找到出口、死亡会失去什么。

### AI 推荐默认方案（待批准）
**D-203 地图**
1. 首版先做一张手工设计的地图骨架，局内对普通敌人种类/位置、资源点、宝箱、少量事件及部分精英遭遇进行有限随机化。
2. 地图骨架包含入口、中心连接区、两条中段支线、深处高风险区和至少一个撤离点。
3. 关键地标清楚；出生点安全；所有关键兴趣区保持可达；随机化不得封死撤离路线或强制 Boss 遭遇。
4. 每局约 3–5 个兴趣点作为初始密度测试目标，不是冻结数量。

**D-202 撤离与死亡**
1. 撤离点固定在地图骨架中、可提前发现且始终可达；玩家获得满意战利品后可主动提前撤离。
2. 进入撤离区域后主动启动读条；离开区域、主动取消或死亡时中断；单纯受伤但未死亡不自动中断。
3. 死亡时丢失本局尚未成功撤离的战利品；仓库资产、永久解锁与基础出战能力保留。
4. Boss 为可选高风险目标，不阻止玩家撤离；撤离点增援仅作为有限、可读、可反制的可选压力机制，不做无限刷怪。

### 可选替代方案
- 地图：全程序生成（变化更多、可读性与测试成本更高）；或完全手工地图（可控但重玩变化较少）。
- 死亡：仅丢失部分战利品；或额外扣除少量局外资源（压力更高，不建议首版默认）。
- 撤离：受伤也中断读条；或撤离必须清空区域敌人。两者都会提高压力并可能造成挫败。

### 影响范围
FR-MH-01/05/06/07/08/09/11；M1 地图骨架、掉落、撤离与死亡结算；D-202 的资产规则会直接约束 D-205 背包和 D-206 资源循环。

### 留给原型验证的数值/行为
撤离读条约 6 秒、区域半径约 3.0 世界单位、兴趣点数量约 3–5、路线长度、敌人增援数量与出现时机均为测试起点。撤离点数量的最低规则建议为至少一个固定点，但后续地图扩展可再讨论。

## 3. 第三组：装备、构筑与营地成长 — D-205 + D-206

**需要解决的问题：** 搜到的东西如何改变战斗；撤离后的资源如何转化为下一局准备与长期目标。

### AI 推荐默认方案（待批准）
**D-205 装备**
1. 首版采用简化装备结构：武器、防具、饰品三个候选槽位；若手机 UI 或内容成本过高，可缩减槽位，但必须保留玩法行为差异。
2. 装备以固定效果或少量可控词条为主，不做庞大随机词缀池、套装、合成、重铸。
3. 稀有度可采用普通/优秀/稀有/史诗四档作为视觉与价值分层；实际掉率不在阶段1冻结。
4. 最低完成两种明显不同构筑：远程法杖与近战魔剑；第三种技能强化构筑作为争取目标。
5. 背包满时禁止新拾取并明确反馈；高风险不可逆操作需确认或可撤销。

**D-206 营地**
1. 首版营地聚焦仓库/整备 + 简单兑换 + 少量装备选项解锁。
2. 先使用一种主要局外货币；永久成长优先解锁新装备/效果选择，不依赖无限永久属性堆叠。
3. 营地先以轻量场景或界面呈现，不做自由装修、复杂 NPC 关系、多级材料链或庞大技能树。
4. 撤离成功后战利品入仓库；资源兑换与永久解锁遵循 D-202 的死亡/保留边界。

### 可选替代方案
- 装备：两槽简化（武器 + 通用装备）；或增加更多槽位/随机词条，但须说明手机管理成本和内容制作量。
- 成长：营地建筑升级；或角色技能树。两者都比简单解锁更重，且须控制永久数值膨胀。
- 稀有度：三档或不设稀有度，改用效果标签区分。

### 影响范围
FR-MH-06/09/10/11/15；M1 只验证最小拾取/背包状态，不要求完整装备与营地；M1 后再完成完整构筑、仓库、兑换和解锁。

### 留给原型/后续平衡验证
装备槽位最终数量、每类装备数量、稀有度掉率、商店价格、货币产出/消耗、永久解锁节奏、背包容量、物品替换体验均需数据与可用性验证。至少两种构筑为最低要求、第三种为争取目标，不因本建议改变。

## 4. 第四组：世界观与新手引导 — D-208 + D-209

**需要解决的问题：** 玩家为什么进入失落领域；如何不依赖外部说明就学会核心循环。

### AI 推荐默认方案（待批准）
**D-208 世界观**
1. 采用轻量背景：魔法文明曾繁盛，未知裂隙事件使区域与外界隔离；玩家作为探索者进入区域搜寻遗物、装备和资源，再撤离返回营地。
2. 营地是安全的远征整备据点；商人/服务角色仅承担功能职责。
3. 通过遗迹、环境物件和少量短文本表达世界信息；不做长篇对话、过场或复杂任务线。
4. “裂隙探索者”和“Shadowgrove”均为暂名，不冻结正式角色名/地图名。

**D-209 引导**
1. 首局轻量引导布局 + 首次触发时的渐进情境提示。
2. 依次覆盖移动、自动普攻、手动技能、拾取/背包、撤离与死亡结算。
3. 每次只出现一个短提示；危险战斗期间延后非紧急提示；允许跳过、关闭与重新查看。
4. 首局敌人压力可略低，但不改变核心规则；手机提示避开操作区，PC 键位提示依 D-201 最终批准结果生成。
5. 死亡/撤离文案必须严格依 D-202 最终规则生成。

### 可选替代方案
- 世界观更极简：只用环境叙事，不定义裂隙事件；或增加少量可选短文本日志，但不引入长篇剧情。
- 引导只做渐进提示，不做首局特殊布局；或采用单独教学局。单独教学局成本较高且可能与正式节奏脱节。

### 影响范围
FR-MH-05/12；首图主题、美术资产与环境叙事；首局无外部说明可理解性；引导依赖 D-201、D-202、D-203、D-205、D-206 的稳定规则。

### 留给验证
提示出现时机、停留时长、可跳过率、首局完成率、玩家对死亡损失/撤离意义的理解程度；世界观文本数量与地图视觉可读性。

## 5. 跨组依赖与建议冻结顺序

1. **先定第一组（D-201/D-204）**：输入布局影响 Dash 与技能按钮空间。
2. **再定第二组（D-202/D-203）**：地图撤离结构和死亡资产规则共同定义风险循环。
3. **再定第三组（D-205/D-206）**：装备、仓库与货币循环必须服从死亡/撤离资产规则。
4. **最后定第四组（D-208/D-209）**：引导文案依赖前面已经稳定的真实规则。

建议一次审查四组，不要求逐条来回问答。负责人可以直接引用组名和 D 编号给出批准/修改/暂缓结果。
