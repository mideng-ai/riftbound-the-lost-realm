## 1. 使用规则

1. 本文件将 `GAME_SCOPE.md` 当前 15 项 Must-have 拆为可追踪的功能需求（FR-MH-01～15）；原始范围含义不扩大、不缩减。
2. 「验收条件」描述可观察结果。凡依赖 D-201～D-206、D-208、D-209 的规则，均以负责人已确认的设计基线为准；数值与体验参数按验证计划处理。
3. 状态区分为：
   - **范围条目存在：** 当前 GAME_SCOPE 已列出该需求；
   - **设计待确认：** 仅用于尚未确认的独立事项（当前主要为 D-104 怪物目标数量）；八项已确认设计方向不再归入此状态；
   - **阶段2技术验证：** 产品需求已列出，但技术实现/性能门槛留给阶段2。
4. M1 覆盖仅表示阶段3垂直切片可验证的最小部分，不表示首版交付，也不代表 M1 已获批准。
5. 任何未由负责人明确确认的数值、数量或技术方案，不得从验收文字推导为已批准规则；已确认的输入方式、死亡资产边界与系统方向按 DECISIONS_LOG v4.6 执行。

## 3. 逐项功能规格

### FR-MH-01 — 单局完整流程

**产品需求：** 贯通进入、探索搜刮、战斗、撤离或死亡、结算；目标单局 10–15 分钟。

**用户价值：** 提供可重复、可理解且有明确风险/收益结局的核心游戏循环。

**行为规格：**
- 贯通进入、探索搜刮、战斗、撤离或死亡、结算；目标单局 10–15 分钟。
- 具体状态、交互、参数与边界情况以对应 D 编号批准后的专项规格为准；本文件不补写未决规则。

**验收条件：**
- 玩家能完整开始并结束一局，且撤离与死亡均有可到达的结算路径。
- 需求涉及双端时，分别在手机浏览器和 PC 浏览器执行适用的验收路径；平台性能阈值按 D-210 阶段2实测结果定义。
- 记录测试设备/浏览器、版本、前置条件、步骤、预期结果、实际结果与未覆盖项；不得以文档检查代替实际运行测试。

**依赖：** D-202、D-203；关联 D-201、D-204、D-205、D-206

**M1 覆盖边界：** M1 只覆盖可玩原型所需的最小闭环；不得据此要求完整首版内容。

**当前状态：** 需求已列入当前 GAME_SCOPE；详细交互/内容参数须在对应设计阶段确认。

**风险与非目标：**
- 不因本条拆分而增加新功能、扩张首版范围或提前承诺未批准的数值。
- 完整打磨目标（视觉表现、额外内容、丰富反馈等）不自动成为首版最低验收门槛。
