### 5.2 浏览器运行时复现：结算屏仍是全 0（关键发现）

沿用技术总监的 Chromium + Xvfb 快进路径，我**独立重跑**（脚本落盘 `evidence/qa-d207-final/browser-probe.py`）：

- 命令：`?t=600&killboss=1&mute=1&debug=1`，截图 `evidence/qa-d207-final/qa-d207-settlement-smoke.png`，原始 JSON `browser-probe.json`。
- 结果：`probe().economy = { gold:0, forestMaterial:0, gems:0, runsPlayed:1, bossKills:1 }`；结算屏 Victory / Survived 10:00，**Gold/Wildwood/四碎片/Gems 全部为 0**；落盘主档 `forestCore:1, bossKills:1, runsPlayed:1` 正确。
- **与技术总监提交的 `evidence/td-d207-settlement-smoke.png` 完全一致：结算屏全 0。** 他的自报只声称「结算屏渲染 + bossKills=1」，并未声称货币非零——这点他诚实；但所有者本轮验收要的是「结算货币非零」，两者之间存在证据缺口。

**为什么全 0（分析，非开脱）**：快进路径里 Boss 在 `bossSpawnPos(0,0,-8)` 被秒杀，地面掉落在 z=-8；玩家在 (0,0)，拾取半径 `PICKUP_RADIUS_M = 0.7×3 = 2.1m`，8m > 2.1m → 永远拾不到；且快进跳过了普通击杀，账本本就为空。这**是取证路径的限制**，不能反证链路断裂（G1 已证链路有效），但**确实说明：目前没有任何一条浏览器证据能证明「玩家击杀→拾取→结算非零」**。

我又补跑了 4 条路径试图产出正面证据，全部未成功：

| 路径 | 脚本 / 证据 | 结果 |
|---|---|---|
| 预置富档（gold=999 等）快进 | `browser-seeded.py` / `browser-seeded.json` | 读档正确、统计 10→11 / bossKills 3→4 / core 2→3、无竞态；但**无拾取发生**，货币保持 999 不变，结算屏仍无新增拾取 |
| 近战 + WASD 绕圈 10s | `browser-realplay.py` | phase=defeat，账本全 0（自动化未打出有效击杀，XP=0） |
| 法杖持续开火 22s | `browser-realplay2.py` | phase=defeat，XP=0、账本全 0 |
| 近战走动撞击怪潮 12s | `browser-realplay3.py` | phase=running，XP=0、账本全 0 |

### 5.3 新发现：Boss 掉落生成晚于结算快照（DEF-006）

代码走查发现一处确定性时序缺陷：

1. `VictorySettler.settle()` 在 `combat.bus` 发 `boss.defeated`（`src/boss/victory.ts:41`）。
2. `EventBus.publish` 按监听器**插入顺序**同步分发（`src/domain/events.ts:136`）。
3. `bossBridge` 在 `BootstrapScene.ts:459` 构造，其构造器（`BossCombatBridge.ts:86-92`）先订阅 `boss.defeated` → 调 `setPhase('victory')` → 同步发 `run.phaseChanged` → `offPhase` → `publishSettlement(true)` → `economy.settleRun()` 在**第一个 await 前**于 `system.ts:164` 立即快照 `credited = ledger.buildRunLoot()`，并同步发 `run.settled`（账本此刻为空）。
4. `offBossDefeatedEconomy` 在 `BootstrapScene.ts:578` **之后**才订阅同一事件 → 此时才 `rollDropsForKill` 生成 Boss 地面掉落。

后果：**Boss 掉落的金币（80-120）、材料（10-15）、宝石、碎片是在账本快照之后才铺到地面的**，胜利结算取不到它们；而 `settled` 标志又阻止二次结算。因此**任何胜利局里 Boss 掉落都无法被本局结算入账**（森林核心 core 通过 `bossDefeated` 入参单独入账，不受影响）。这是「掉落统一选 A」接线引入的真实回归，属所有者点名要查的「Boss 掉落会不会漏」。

> 该缺陷由代码顺序确定性推得（监听顺序 + `credit` 快照在首个 await 前）；其玩家可观察后果建议补一条单测固化（数组顺序 + 结算报告断言），本终验未改业务代码 / 既有测试，故仅在报告中登记。

### 5.4 DEF-004「3 个消费者」核实

`economyView` 全仓 3 处调用：`playerSnapshot.gold`（L649）、`probe().economy`（L842-846）、对外导出（L815）。核实：
- `probe().economy` 是**真读**，且是我本次运行时取证唯一能读到真实落盘经济状态的端口（QA 价值成立）；
- 对外 `economyView()` 导出无仓内二次消费者（ADR「UI/重开数据源」仍未真正落地，同 DEF-004 观察）；
- `playerSnapshot.gold = economyView().currencies.gold`（L649）虽写入 `PlayerSnapshot`，但全仓 grep 显示 `player.gold` 在 enemy/combat 侧**无任何读取点**（仅 `defaultDropTable.ts` 与 `types.ts` 出现），属**惰性消费者**。

结论：从「零消费者」变「有消费者」是进展，但 3 个里 1 个是 QA 取证、1 个惰性、1 个无二次消费；按「真读、不是摆设」的严格口径判 **CONCERNS（低）**，不阻塞关闭。

## 七、新缺陷清单

> 严重度（S1-Critical / S2-High / S3-Medium / S4-Low）与优先级（P1-Fix this sprint / P2-Fix soon / P3-Backlog / P4-Won't fix）分开记录。

### DEF-006 — Boss 地面掉落晚于结算账本快照，Boss 掉落永不被本局结算入账
- **Severity**: S2-High ｜ **Priority**: P1-Fix this sprint
- **Category**: Gameplay / Economy ｜ **Frequency**: Always（每次 Boss 胜利）｜ **Regression**: **Yes（本轮「掉落统一选 A」接线引入）**
- **复现步骤**：① 开局至 Boss 登场 → ② 击杀 Boss（或 `?t=600&killboss=1`）→ ③ 观察结算账本 / 存档：core+bossKills 入账，但 Boss 掉落的 gold/material/gem/shard 未入账
- **期望**：Boss 击杀掉落应能在结算时入账（至少在玩家拾取范围内）
- **实际**：`boss.defeated` 的两个订阅者顺序为「结算快照在前、Boss 掉落生成在后」（§5.3）；结算取空账本，`settled` 又阻止二次结算
- **技术上下文**：`src/boss/victory.ts:41`、`src/combat/BossCombatBridge.ts:86-92`、`src/scenes/BootstrapScene.ts:459/578`、`src/economy/system.ts:164`
- **建议**：将 Boss 掉落生成提前到结算之前，或改为 Boss 掉落直接进本局账本；补单测固化事件顺序与结算报告

### DEF-007 — 拾取半径硬编码集成层常量、且自动拾取可能让远程击杀掉落难以收集
- **Severity**: S3-Medium ｜ **Priority**: P2-Fix soon
- **Category**: Gameplay / Economy / Tech-debt ｜ **Frequency**: Often ｜ **Regression**: No（最小可用方案固有）
- **事实**：`PICKUP_RADIUS_M = PLAYER_MESH_DIAMETER_M * 3 = 2.1m`（`BootstrapScene.ts:356-357`）是集成层硬编码常量，未入 `config/`，与项目「数值集中 config」原则不符（与既有 `DEMO_PROJECTILE_SPREAD_DEG` / `DEMO_MAX_RANGE_M` 同类债务）。且无手动拾取键 / 碰撞 / 动画，法杖射程 28m 下远程击杀的掉落会落在拾取半径外，玩家须逐一走过去。
- **对派单疑点的回答**：担心的「一靠近就吸走所有掉落、破坏搜刮决策」**未发生**（2.1m 反而偏小）；真实风险是相反方向——远程击杀掉落易漏收。请玩法设计总监裁定拾取手感与半径是否入 config。

### DEF-008 — 「结算屏货币非零」缺运行时证据（证据缺口，非已证代码缺陷）
