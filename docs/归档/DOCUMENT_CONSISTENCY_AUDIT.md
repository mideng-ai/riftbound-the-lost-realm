## 2. 已确认的一致基线
1. 项目是 3D 俯视/斜俯视、单人 PvE 魔法搜打撤游戏，四大支柱为战斗、探索搜刮、撤离决策、装备成长。
2. 首发目标仍是 PC 与手机浏览器；开发顺序明确为先手机核心体验，再适配 PC。
3. 手机左手移动；PC 与手机普通攻击均自动触发、自动判断攻击方向；无有效目标时停火。
4. 自动选敌原则为「附近威胁优先 + 距离辅助」，参数留待原型验证。
5. 首个小版本只实现手动特殊技能；自动技能及自动/手动模式 UI 延后研究。
6. 两种普通攻击已确认：法杖远程攻击；魔法剑 120° 扇形、中等距离、标准挥砍，初始目标约每秒一次；具体距离、伤害、动作及反馈仍需验证。
7. M1 是阶段3的最小单局垂直切片，不是首版完整发布版本。
8. D-201 至 D-206、D-208、D-209 仍须负责人逐项确认；D-207 与 D-210 留到阶段2。

## 3. 发现的问题与处理

### AUD-001：M1 首要验收设备表述不一致
- 原问题：PROJECT_OVERVIEW.md 将 M1 描述为普通 PC Chrome 单局切片；GAME_DESIGN_SPEC.md 第4.1节明确 M1 优先以手机浏览器作为主要可玩验证目标。
- 依据：负责人已确认「先完成手机端核心体验，再开发和适配 PC 端」，双平台首发目标不变。
- 处理：将 PROJECT_OVERVIEW.md M1 描述统一为手机浏览器首要可玩验收目标；PC Chrome 保留基础加载/兼容冒烟测试，完整 PC 操作与 UI 适配按后续顺序完成。
- 状态：已修正（本次提交）。

### AUD-002：旧版自动技能讨论容易被误读为首版要求
- 现状：GAME_DESIGN_SPEC.md 保留自动技能动态优先级及技能类别讨论，但已明确标注为后续版本研究项；首个小版本仅手动技能。
- 处理：不删除历史讨论，后续审查与开发任务引用时必须以最新 DECISIONS_LOG 决定为准。
- 状态：无需修改；已有状态标签足够。

### AUD-003：旧聊天中的玩法扩展与正式范围不一致
- 现状：早先对话出现过大量技能、固定营地建筑、四装备槽、每局必打 Boss、Dash 参数等扩展提案；这些不属于负责人已确认规则。
- 处理：以 GAME_SCOPE、DECISIONS_LOG 和 GAME_DESIGN_SPEC 为准；所有扩展内容只作为候选，未批准不得进入 M1 或首版范围。
- 状态：已在 STAGE1_EXECUTION_PLAN.md 的「不得误用的旧提案」中设防。
