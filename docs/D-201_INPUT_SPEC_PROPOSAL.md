# D-201_INPUT_SPEC_PROPOSAL — 双端操作与首版技能输入提案

> 版本：v0.1  
> 日期：2026-11-12  
> 状态：AI 推荐提案，等待项目负责人审查；不是已确认开发规格  
> 项目：Riftbound: The Lost Realm

## 1. 已确认的硬约束

- 手机左手控制移动。
- 手机与 PC 普通攻击均自动触发并自动判断攻击方向。
- 没有符合攻击条件的有效敌人时停止普通攻击。
- 自动选敌原则为「附近威胁优先 + 距离辅助」。
- 首个小版本特殊技能只采用手动施放；自动技能与模式切换 UI 暂不实现。
- 首个小版本包含 1 名角色、2 种武器、2 种特殊技能。
- 手机核心体验先开发，之后适配 PC；首发仍包含手机与 PC 浏览器。

## 2. 手机端推荐输入

### 2.1 推荐屏幕方向
**推荐：横屏。状态：待负责人确认。**

理由：横屏更容易同时容纳左侧移动摇杆、右侧技能按钮与中间战斗视野；但需要在真实手机上验证单手触达、屏幕比例和浏览器安全区。

### 2.2 推荐布局
- 左下区域：虚拟摇杆，负责角色移动。
- 右下区域：两个独立手动技能按钮。
- 普通攻击：无攻击按钮，系统按已确认规则自动攻击。
- HUD：生命、必要资源、技能冷却放在不遮挡主要战场的位置。
- 所有触控区域避开系统手势边缘和浏览器安全区。

### 2.3 技能交互
**推荐：首版两种技能均采用点击即施放。**

- 范围输出技能：点击后以角色为中心释放，避免手机小屏幕精确拖拽瞄准。
- 防御技能：点击后立即生效。
- 冷却中、资源不足或施放条件不满足时，按钮给出短暂视觉反馈，不触发技能。
- 技能按钮按下时提供即时视觉反馈；设备振动作为可选增强，不作为功能依赖。
- 若最终技能效果必须指定方向或落点，再针对该技能单独设计按住拖动瞄准；不把复杂瞄准应用于所有技能。

## 3. PC 端推荐输入

- WASD：角色移动。
- Q：特殊技能1。
- E：特殊技能2。
- 普通攻击：系统自动触发，无需鼠标点击。
- 鼠标：UI 交互；首版不默认加入鼠标手动指定普攻目标。
- 若 D-204 最终确认独立 Dash，建议 PC 使用 Space；手机端另设一个清晰的闪避按钮。Dash 是否存在仍由 D-204 决定，不在本文件预先冻结。

## 4. 普通攻击规则边界

### 已确认
- 自动触发、自动判断方向。
- 无有效目标时停火。
- 附近即时威胁优先，其次按威胁类别与距离辅助选敌。
- 目标尽量保持稳定，明显更高优先级威胁出现时才切换。

### 推荐但待确认
- 玩家移动时允许普通攻击继续进行。
- 攻击动作/弹体已经开始后，不因轻微距离变化立即中断当前攻击。
- 当前目标死亡、失效、离开有效范围或出现明显更高优先级威胁时，重新选敌。
- 魔法剑挥砍开始时锁定本次挥砍方向；一次挥砍的判定窗口内不随目标切换而瞬间转向，以保证动画和命中判定一致。
- 法杖弹体发射后沿发射方向飞行，不在空中瞬间追随新目标；是否采用追踪弹属于后续武器效果，不属于基础攻击。

### 留待原型验证的参数
- 法杖攻击间隔、射程、弹速。
- 魔法剑中等攻击距离对应的世界单位、攻击判定窗口、伤害。
- 自动选敌有效范围、视线/遮挡、目标保持时间和切换阈值。
- 移动中攻击是否造成操作或画面反馈冲突。

## 5. Dash 与技能按钮冲突处理

D-204 尚未确认，因此本提案不把 Dash 作为已存在功能。

若负责人批准 Dash：
- 手机界面预留第三个战斗动作按钮位置。
- 该按钮与两个技能按钮在视觉形状和位置上明确区分。
- Dash 按钮应易于右手拇指触达，不遮挡技能按钮。
- PC 暂定 Space。
若负责人不批准 Dash，则不保留无意义的空按钮。
