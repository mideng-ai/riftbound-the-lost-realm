## 0. 结论与前置确认（给项目所有者）

**结论：CONCERNS。** 本规格用 Babylon 内置几何体 + 纯色材质，100% 可实现「深色虚空 → 失落森林」的过渡，且全部颜色取自美术圣经 V0.5，无需任何图片文件。但有 3 项需要拍板/澄清，不阻塞动手、但会影响返工量：

## 1. 人话开头：为什么这么做，以及它和「真美术资产」的关系

现在的试玩画面之所以是「一个一个圆圈」飘在黑里，不是设计意图，而是三件事叠加：地面材质几乎全黑、只有一盏环境光没有主光、实体用自发光纯色平涂。摄像机看不见边界与障碍，玩家自然觉得「地图和人物没了」。

**为什么用程序化几何**：出图工具（ImageGen）429 额度不足、Nano Banana Pro 无 API key，美术资产这条路暂时走不通；而 Babylon 的基础几何体（地面、圆柱、方块、球）+ 纯色材质不需要任何图片文件，当天就能让场地立起来。

**目标观感**：不是照片级森林，而是 A08 mood sheet 的**程序化近似**——有绿色地面、能看出小径和苔藓、有树有石头有遗迹、四周有边界、有雾有明暗层次、球和方块不再是纯色平涂。

**与「真美术资产」的关系**：这是**过渡方案，不替代未来的模型/贴图**。本文所有 `env_*` 形状都是临时的占位几何，等美术资产到位后按美术圣经 §7/§8 的命名与预算替换即可，本文档的颜色、光照、相机、雾参数可继续沿用。

## 2. 相机与光照

> 人话：相机决定「能看见多少」，光照决定「东西有没有立体感」。现在平涂的根源是缺一盏主光；相机也太垂直了，几乎从头顶往下拍，看不到树的侧面。

### 2.1 相机（ArcRotateCamera，沿用现有 CameraRig 实例，只调参数）

| 参数 | 现值 | 建议值 | 说明 |
|---|---|---|---|
| `beta`（极角，0=正上方） | `0.3` rad ≈ **俯角 72.8°** | **`0.56` rad ≈ 俯角 58°** | 落在圣经/A08/A09 的 55–60° 区间；能看到树干侧面与层次 |
| `radius`（视距） | `34` | **`30`** | 主体更大；见下方视野校验 |
| `upperRadiusLimit` | `48` | `48`（保留） | 不改 |
| `lowerBetaLimit` / `upperBetaLimit` | `0.2 / 1.35` | `0.45 / 0.75`（收紧） | 锁定俯视角，符合圣经 §5「CameraRig 锁定俯视角」 |

**视野校验**：俯角 58°、radius 30、默认 FOV 0.8 rad 时，画面短边覆盖约 ±16–18m、长边约 ±26–30m；玩家周围 12m 安全生成圈完整可见（BootstrapScene 注释里 12–20m 的怪潮需求）。若作者坚持 55° 更平视，用 `beta=0.61`；**不要低于 55°**，否则远处的怪会被地平线裁掉。

### 2.2 光源配置（颜色全部出自圣经 §2 与 §1）

| 光源 | Babylon 类型 | 颜色 HEX（圣经出处） | 强度 | 方向 / 参数 |
|---|---|---|---|---|
| 主光 | `DirectionalLight` | **`#FFF4E0`** 暖白（§2） | **`1.15`** | 方位「北偏西 30°」、仰角 55°；世界方向向量 **`new Vector3(0.29, -0.82, 0.50)`**（由方位角/仰角换算，light 朝地面传播） |
| 环境光 | `HemisphericLight`（替换现有白色 hemi） | 天空 **`#BFE3D8`** / 地面 **`#4A6741`**（§2） | **`0.55`** | 方向 `(0.2, 1, 0.1)`（沿用现值与天空向上一致） |
| 补光 | **不加** | — | — | 圣经 §2 的 rim light 仅玩家/精英/Boss 强度 0.35，属于材质层方案，本过渡版用「实体 emissive 微光」近似（见 §5），不新增第三盏动态光 |

> 现有 `new HemisphericLight('hemi',...).intensity = 0.6` 是白色默认光，**没有主光**——这就是 toon 三档明暗出不来、地面发灰的直接原因。必须补 `DirectionalLight`。

### 2.3 雾（teal mist）

| 参数 | 建议值 | 说明 |
|---|---|---|
| `scene.fogMode` | `Scene.FOGMODE_LINEAR` | 线性雾最可控、最省性能 |
| `scene.fogColor` | **`#A8D8D0`** 雾霭青（§1 环境主色，A08 的 teal mist 就取这一色） | 同时把 `scene.clearColor` 也设为该色，屏幕边缘与雾无缝衔接，「虚空黑」彻底消失 |
| `scene.fogStart` | **`25`**（米） | 玩家周围 25m 内清晰，覆盖安全生成圈 |
| `scene.fogEnd` | **`55`**（米） | 场地对角约 85m；远端边缘淡出，制造「森林没有尽头」的错觉 |
| `scene.clearColor` | `Color4` from `#A8D8D0`, alpha `1` | 替换现值 `(0.043,0.051,0.071)` ≈ `#0b0d12` |

**已知限制（提前告知技术总监，别踩坑）**：Babylon 自定义 `ShaderMaterial`（现有 `ToonMaterial`）默认不吃 scene fog，雾只会作用在地面/树/石等 `StandardMaterial` 上。**这是好事**——实体保持清晰可读、环境淡出，正好符合可读性优先；不需要给 toon shader 加雾。

### 2.4 明暗层次目标

光照到位后，地面与障碍用 `StandardMaterial`（受光）自然产生明暗；实体用 `ToonMaterial` 的三档带（见 §5.2）。判定标准：截图里同一个树冠能看到**亮面/中间面/暗面**至少两档，而不是整块同色。

## 3. 地面规格（核心）

> 人话：地面是「地图感」的全部来源。现在地面其实存在（60×60、y=0），但材质是接近黑的深蓝灰，所以看起来像虚空。做法不是重铺很多块，而是**一张大地面 + 顶点颜色**分出小径/草地/苔藓，一次绘制、又便宜又有变化。

### 3.1 几何与遮挡

| 项 | 参数 |
|---|---|
| 生成方式 | **`MeshBuilder.CreateGround`**，单个 mesh（不要几百块 tile） |
| 尺寸 | **`width = 68, height = 68`**（覆盖可玩 ±30 再外扩 4m，到 ±34；雾里自然淡出，看不到边的硬切） |
| `subdivisions` | **`60`**（61×61 顶点 ≈ 3721 顶点，足够做颜色分区；一个 mesh 一次 draw call） |
| Y 高度 | **`y = 0`**（保持现值）；玩家/怪的 Mesh 中心在 `y = radiusM`，天然在地面之上，无需改 depth |
| 是否遮挡正确 | 地面不透明、`isPickable = false`；实体背靠地面即可正确遮挡。预警贴花已用 `y = 0.03` 抬离（BossTelegraphView 的 `LIFT_Y`），继续沿用 |
| 顶点色 | 用 `VertexBuffer.ColorKind` 写入每顶点颜色；`StandardMaterial.diffuseColor` 设白色使顶点色生效 |

### 3.2 分区方案（全部取自圣经 §1 环境主色，HEX 不得改）

| 分区 | HEX | 圣经出处 | 地面面积占比* | 分布规则 |
|---|---|---|---|---|
| 草地底（base） | **`#2E7D4F`** 深林绿 | §1 环境主色 | **~65%** | 默认底色，铺满整张地面 |
| 泥土小径（path） | **`#7A5230`** 泥土棕 | §1 环境主色 | **~18%** | 两条宽约 3–4m 的交叉土路，一条沿 X 轴、一条沿 Z 轴穿过原点，边缘用噪声抖开，别画成笔直的十字 |
| 苔藓亮斑（moss） | **`#8FD14F`** 嫩芽绿 | §1 环境主色 | **~12%** | 散布在草地上、树根附近，半径 1–3m 的不规则斑块 |
| 碎石/遗迹地（stone） | **`#C9C2B4`** 遗迹石灰 | §1 环境主色 | **~5%** | 只在 2 处 `ruin` 障碍周围 3m 内出现 |

\* 这是**地面表面**的面积占比，不是圣经 §1 的「同屏画面占比」（那个含天空、实体、UI）；两者口径不同，不要互相套用。四色合起来仍只用圣经环境主色里的四个，没有引入新色。

### 3.3 程序化变化（固定 seed，可复现）

1. **底噪**：按顶点 `(x, z)` 与固定 seed `1337`，用确定性伪随机在每个顶点上做三选一：以 65/18/12/5% 的权重落在上表四色之一；**同一 seed 每次运行颜色完全一致**（符合设计总纲 §3.4「随机系统必须支持 seed」）。
2. **空间相关**：不要纯逐顶点随机（会像噪点电视）。用「粗网格值噪声」：先把地面划成 4m 格，每格随机一个分区色，再让格内顶点有 15% 概率取相邻色，得到斑块而非雪花。
3. **暗部偏移**：按圣经 §2 规则，朝暗面的顶点把颜色向雾霭青 **`#A8D8D0`** 做 **15%** 的线性插值（lerp），得到 toon 暗档的冷色偏移——这是**由圣经色推导的明度变体，不是新色**。
4. **路径优先**：落在小径带内的顶点强制用 `#7A5230`，只在其边缘 0.5m 内参与噪声，保证「路」始终读得出来。

> 若顶点色在你的 Babylon 版本上调试困难，**退路**：改成 4 张 `CreateGround` 叠放（y=0/0.01/0.02/0.03，分别草地/小径/苔藓/碎石），各 1 个 StandardMaterial。视觉等价，代价多 3 个 draw call。

## 4. 障碍物与边界

> 人话：树、石头、遗迹让场地「有东西可躲」，也让玩家和怪能被正确挡住。好消息是逻辑侧已经有 8 个固定障碍的位置，渲染只要照着摆，不用重新生成——这样「看到的墙」和「撞到的墙」是同一堵。

### 4.1 障碍物（**直接复用 `arenaConfig.ts` 的 `ARENA_OBSTACLES`，不要另造坐标**）

现有 8 个固定障碍：4 tree / 2 rock / 2 ruin，半径 1.2–2.0m。渲染几何与圣经色对照：

| kind | 几何体（Babylon 内置） | 视觉尺寸 | 颜色 HEX（圣经 §1） | 数量 |
|---|---|---|---|---|
| `tree` 树干 | `CreateCylinder`（`diameterTop` 略小于 `diameterBottom`，如 0.8× 与 1× 半径） | 高 4–6m，碰撞半径 = `radiusM` | **`#7A5230`** 泥土棕 | 4 |
| `tree` 树冠 | `CreateSphere` 或 `CreateCylinder`，压扁放顶部 | 直径 ≈ `radiusM × 2.2` | **`#2E7D4F`** 深林绿（底部暗面混 `#A8D8D0` 15%） | 4 |
| `rock` | `CreatePolyhedron`（type 1，低面数）或 `CreateBox` 旋转 | 直径 ≈ `radiusM × 2` | **`#C9C2B4`** 遗迹石灰 | 2 |
| `ruin` | `CreateBox` 立柱 2–3 根 + 顶部横梁 | 高 3–4m，占 `radiusM` 范围 | **`#C9C2B4`** 遗迹石灰；缠绕藤蔓用 **`#8FD14F`** 嫩芽绿（细 cylinder 或 box） | 2 |

**关键约束**：
- **视觉半径 = 碰撞半径**：树干/石头在地面上的投影半径必须 ≈ `radiusM`，否则会出现「看得过去却撞墙」或「撞不到却卡住」——这是美术圣经 §4.3「贴花几何 = 判定几何」红线在同处的体现。
- **分布规则**：位置完全沿用 config 的 8 个点，已手工避开玩家出生点 `(0,0)`；**不要随机撒进可玩区**。
- **数量上限**：可玩区内 **8 个（硬上限，必须等于 config）**。若想加纵深，只能在 **±30 之外**加装饰树（纯视觉、不参与碰撞、`isPickable=false`），总数 **≤ 24**，全部落在雾里；手机端中配建议更保守取 12。
- 材质复用：4 类几何各共享 1 个材质（共约 5–6 个），不要每个障碍 new 一个材质。

### 4.2 边界可视化（把 ±30 画成「藤蔓雾墙」）

| 项 | 参数 |
|---|---|
| 几何 | **4 片竖直 `CreatePlane`**（或厚 `CreateBox`，depth 0.3），沿 x=±30 / z=±30 各一片，高 **3.5m**，长 **60m** |
| 颜色 | **`#A8D8D0`** 雾霭青（§1），`emissiveColor` = 同色、`diffuseColor` = 同色 |
| 透明度 | **`alpha = 0.30`**，`backFaceCulling = false`（从场内外都能看见） |
| 附加读法 | 在四角与中点加 8 根细 `CreateCylinder`「发光藤柱」，颜色 **`#8FD14F`** 嫩芽绿、`alpha 0.5`，高度 4m；让边界读作「森林围墙」而非「空气墙」 |
| 性能 | 4 面 + 8 柱 = **12 个 mesh，2 个共享材质**；`isPickable = false`，不参与任何判定 |
| 备选 | 若嫌平面太「玻璃」，改用一圈低矮 `CreateBox` 石块（`#C9C2B4`，高 0.8m、间隔 3m，约 80 块）——**不推荐**，draw call 高且挡视线 |

> 边界只是视觉提示；真正的夹取仍由 `Arena.clampPosition` 负责（±30），两者位置必须对齐，别让墙画在夹取范围外面。

### 5.2 toon 三档怎么用材质近似（给技术总监的可行做法）

**推荐（首选）：继续用现有 `ToonMaterial`（ShaderMaterial），只改两个参数**
- 把 `gameConfig.render.toonBands` 从 `[0.08,0.44,0.78]` 改成 **`[0.22,0.55,0.85]`**（圣经 §2 定案，硬边）。
- 把 fragment 里的暗部基色从当前 `(0.22,0.24,0.3)`（偏蓝灰）改为**向雾霭青 `#A8D8D0` 偏移 15% 后的环境色**，即 `ambientColor ≈ (0.28,0.33,0.32)` 量级（圣经 §2「暗部不压黑，向雾霭青偏移 15%」）。
- 玩家、精英、Boss 用 ToonMaterial；三档由 shader 的 `step()` 直接给出，这是最贴合圣经的方案。

**替代（若 shader 调试受阻）：`StandardMaterial` 近似**
- `specularColor = Color3.Black()`（去高光，卡通感）
- `diffuseColor = 主色`，`emissiveColor = 主色 × 0.12~0.18`（微光防死黑）
- 环境光 + 主光的 Lambert 明暗会自然形成「亮/中/暗」两级，视觉上接近两档 toon；这是**降级近似，不是精确三档**。

**不建议**：`GradientMaterial` 做的是按距离/方向的连续渐变，不是硬边三档，与圣经「三档硬边」相悖。

### 5.3 预警形状颜色核对 —— ✅ 已一致，不改

| 形状 | 技术总监现值（BossTelegraphView） | 圣经 §4.1 | 结论 |

## 6. 性能预算（手机中端 30 FPS）

> 人话：好看的效果很多，但手机会卡。这份规格给自己划了红线：地面 1 张、障碍最多 8+12 个、材质十几个、绘制调用压在 120 以内——在这个范围内既能有层次，又不会掉帧发热。

| 项 | 预算上限 | 本规格实际值 |
|---|---|---|
| 地面 mesh | 1 | 1（CreateGround subdivisions 60） |
| 可玩区障碍 mesh | ≤ 8 | 8（4 树×2 部件 + 2 岩 + 2 遗迹×多部件 ≈ 18 个子 mesh，可 merge 降 draw call） |
| 装饰树（场外） | ≤ 24 | 建议 12 |
| 边界 mesh | ≤ 12 | 12（4 面 + 8 柱） |
| 共享材质数 | ≤ 20 | 地面 1 + 障碍 ~6 + 边界 2 + 实体 ~8 ≈ 17 |
| **总 draw call（静态场景）** | **≤ 60** | 约 40–55（含实体） |
| **峰值 draw call（含 60 怪 + 特效）** | **≤ 120** | 需实测；怪多时优先降粒子而非加静态场景 |
| 动态光数量 | **≤ 2** | 1 Directional + 1 Hemispheric |
| 目标帧 | P95 ≤ **33.3ms（30FPS）**，不触发热节流（圣经 §6） | 需 QA 实测 |

**好看但别做（明确禁止）**：
- ❌ 实时阴影贴图（shadow generator）：中端机成本高，且过渡版没有做阴影的资产需求 → **全关**；如确实需要脚下暗斑，用 1 个扁平 `CreateDisc`（`#1E2A24`, alpha 0.25, y=0.02）当 blob，无贴图。
- ❌ 后处理 bloom / GlowLayer：GPU 开销大；发光感用材质 emissive 近似即可（Boss 核心除外，但也别开全屏 glow）。
- ❌ 多盏动态点光 / 大量透明粒子：动态光每多一盏都要重算顶点；透明层堆叠在手机上很贵。
- ❌ 逐顶点法线重算、高细分球体（segments > 20）、任何需要贴图的方案。
- 降级顺序沿用圣经 §4.2：先关装饰粒子 → 命中粒子减半 → 关拖尾 → 降预警填充透明度（描边不可降）。预警、受击闪白、Boss 核心发光**不可降级**。
