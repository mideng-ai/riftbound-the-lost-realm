## 1. 调研目的与记录规则

本清单用于记录可供《Riftbound: The Lost Realm》评估的第三方资源、工具与开源素材，重点核实来源、许可证、商业使用条件、署名要求、再分发限制及与当前技术路线的适配情况。

记录为“候选”不等于批准使用。正式集成前仍需：
- 核对资源仓库中的当前许可证、NOTICE 和具体文件说明；
- 确认实际使用的文件均被相应许可证覆盖；
- 将必要的版权声明和许可证文本纳入项目；
- 在项目实际技术环境中完成兼容性与视觉风格测试；
- 由项目负责人决定是否采用。

本阶段仅做资料调查和清单记录，不下载资源、不安装依赖、不集成代码，也不改变已选定的技术路线。

本清单版本号以 0.x 递增，表示资源候选清单；0.x 版本须经项目负责人正式验收后方可升级为正式版本（1.0）。在升级 1.0 之前，清单中的任何资源均仅为候选，不代表已获准集成或采用。

### 2.1 PixelFX

| 项目 | 调研记录 |
|---|---|
| 名称 | PixelFX |
| 来源 | https://github.com/patch-gg/pixelfx |
| 类型 | 基于代码的 2D 像素风格特效库，不是 3D 模型资源包 |
| 内容规模 | 仓库 README 介绍包含 244 个像素风格特效，覆盖火焰、爆炸、水、冰、闪电、奥术、暗影、状态效果、拾取物和 UI 等类别 |
| 浏览器相关能力 | README 描述支持浏览器 Canvas，并列出 Phaser、PixiJS、Kaplay、three.js 等使用场景；也支持导出透明 PNG 精灵表及帧数据 |
| 许可证 | 仓库声明代码与特效采用 MIT License，允许商业用途；使用时须遵守 MIT 许可证的版权与许可声明保留要求 |
| 许可证例外 | `gallery/fonts` 中的 Patch Pixel 字体不受仓库 MIT 许可证覆盖，需单独查看该目录的 NOTICE 和字体许可条件；不得默认将该字体纳入 MIT 授权范围 |
| 第三方来源说明 | 仓库 NOTICE.md 说明部分代码/特效改编自 Hugo Duprez 的 MIT 项目，以及 Hollow Crown 的 MIT 项目；使用前应保留并核查相关声明 |
| 可能用途 | 可作为火球、爆炸、冰霜新星、闪电、魔法阵、拾取提示等 2D 特效或 UI 动效的候选参考 |
| 与项目风格的匹配 | 当前项目目标为精致、明亮的 3D 卡通奇幻风格。像素风特效与主视觉可能不一致，不建议未经测试就作为主要战斗特效风格 |
| 与当前技术路线的适配 | 当前项目选择 Babylon.js。PixelFX README 明确列出 Canvas 和 three.js 等场景，但未明确列出 Babylon.js；是否能通过 Canvas 纹理、平面或 UI 叠加方式适配，仍属于待验证事项 |
| 当前状态 | 候选资源；尚未进行 Babylon.js 集成测试、视觉风格测试或实际项目验收 |
| 风险/注意事项 | 项目较新；集成前需检查实际源代码、依赖和许可证文件。不要把其像素特效误认为 3D 模型、材质或完整粒子系统 |

**初步结论：** 可以保留为 2D 像素特效候选资源，尤其适合原型阶段进行效果参考；暂不确定为正式游戏特效方案，不改变 Babylon.js 技术路线。

**核查来源：**
- 项目 README：https://github.com/patch-gg/pixelfx
- 项目 NOTICE：https://github.com/patch-gg/pixelfx/blob/main/NOTICE.md
- 字体许可说明（需在实际采用字体前单独核查）：https://github.com/patch-gg/pixelfx/tree/main/gallery/fonts

## 3. 分类使用说明

### 3.1 PBR 材质与贴图使用说明

PBR 材质通常由多张贴图共同描述表面属性，具体通道因资源而异：
- **Base Color / Albedo：** 表面基础颜色。
- **Normal：** 模拟细节凹凸方向，不等同于真实几何细节。
- **Roughness：** 控制表面粗糙程度和高光扩散。
- **Metallic：** 标记金属属性；并非所有材质都需要。
- **Ambient Occlusion（AO）：** 辅助表现缝隙和局部遮蔽。
- **Height / Displacement：** 提供高度信息；是否使用取决于渲染方案。
- **Opacity / Emission：** 仅在透明或自发光材质需要时使用。

**浏览器项目的性能建议（技术评估建议，尚未在本项目验证）：**
- 先以 1K 纹理作为普通地面和远景材质的评估起点；近景重点物件再考虑 2K。
- 不要把所有下载资源都以 4K/8K 原始尺寸导入。
- 评估纹理压缩、Mipmaps、纹理复用和材质数量；Babylon.js 的具体导入与压缩流程留待技术阶段验证。
- 卡通风格项目不一定需要完整写实 PBR 通道；视觉一致性优先于贴图数量。

### 3.2 音频资源使用与许可证检查规则

正式采用任何音频前，至少记录：
- 素材名称、作者、原始页面 URL、下载日期和文件名；
- 具体许可证名称与版本（例如 CC0 1.0、CC BY 4.0、平台自定义许可）；
- 是否允许商业游戏、修改、循环剪辑和随游戏打包；
- 是否需要署名，以及署名文本应放在游戏内、说明文件还是商店页面；
- 是否禁止独立再分发、素材包再销售或 AI/ML 训练；
- 保存许可页面截图或许可证文本，以及下载时的资源页面。

**常见许可判断：**
- **CC0：** 通常最省心，商业使用无需署名；仍需检查录音本身可能涉及的肖像、商标、隐私等其他权利。
- **CC BY：** 可以商业使用，但必须正确署名并保留许可信息。
- **CC BY-NC：** 带非商业限制，不纳入商业游戏候选。
- **CC BY-ND：** 禁止分享改编版本；游戏剪辑、循环、混音等可能带来许可不确定性，原则上避免作为本项目音频来源。
- **平台自定义许可：** 不能当作 CC0；逐项阅读商业用途、独立分发、打包和署名条款。

### 3.3 音频制作与浏览器游戏建议

以下属于项目制作建议，尚未在本项目技术环境中验证：
- **格式：** 原型阶段保留 WAV 母版；浏览器运行时可评估 OGG/MP3 等压缩格式的兼容性和体积。
- **循环：** 环境音和背景音乐优先选择无缝循环版本；检查循环点是否有爆音或静音间隙。
- **分层：** 将背景音乐、环境音、玩家技能、敌人音效和 UI 音效分组控制音量。
- **音量：** 战斗音效要清楚但避免技能叠加时刺耳；提供音乐、音效独立音量设置。
- **移动端：** 注意首次用户交互后才能可靠启动浏览器音频；避免同时播放过多音源。
- **体积：** 不要把大型音效合集整体放入游戏发布包，只打包实际使用并完成许可登记的文件。

### 3.4 Babylon.js 特效实现路线（技术资料核查）

当前项目已选择 Babylon.js。官方文档确认其提供 sprite 粒子、mesh 粒子、points cloud 粒子、CPU/GPU 粒子系统；GPU 粒子需要 WebGL2，并有部分功能限制。WebGL2 不可用时，需准备 CPU 粒子降级方案并控制粒子容量。

Babylon.js v8.14 起提供 Node Particle Editor（NPE），可以通过节点图设计粒子系统并生成 NodeParticleSystemSet。官方文档当前说明 NPE 生成的是 CPU 粒子系统。它适合用来可视化搭建和调试技能效果；生产项目建议将粒子系统 JSON 保存在项目本地，而不是依赖外部 snippet server。

官方资料：
- 粒子系统概览：https://doc.babylonjs.com/features/featuresDeepDive/particles/
- GPU 粒子说明：https://doc.babylonjs.com/features/featuresDeepDive/particles/particle_system/gpu_particles
- Node Particle Editor：https://doc.babylonjs.com/toolsAndResources/npe/
- NPE 粒子系统文档：https://doc.babylonjs.com/features/featuresDeepDive/particles/particle_system/node_particle_editor/

**针对项目技能的初步实现拆分（设计建议，尚未开发或验证）：**
- **火球：** 发射轨迹 + 火焰粒子 + 尾迹 + 命中爆炸/烟尘。
- **连锁闪电：** 动态线段/曲线或短寿命网格 + 电弧闪光粒子；不依赖大量随机粒子表达主体。
- **冰霜新星：** 地面扩散环/网格 + 冰晶粒子 + 短暂冷色冲击光。
- **魔法护盾：** 半透明球面或弧形网格 + 流动材质/纹理 + 受击闪光。
- **闪现：** 起点/终点短暂能量爆发 + 角色透明度或残影过渡。
- **生命汲取：** 玩家与目标之间的曲线能量束 + 沿线移动的粒子。
- **传送门：** 环形网格 + 旋转/流动材质 + 环绕粒子 + 激活/关闭爆发。

以上为实现方向，不是已完成效果，也不要求本阶段编写游戏代码。

### 3.5 特效性能与风格注意事项

- 粒子数量需要按设备性能设置上限；不要默认使用 GPU 粒子就可以无限增加粒子。
- GPU 粒子只在 WebGL2 可用时启用，并保留 CPU 粒子或简化特效作为兼容降级路径。
- 对同一类效果复用粒子贴图和材质，减少材质种类与重复资源。
- 大量战斗同时发生时，优先保证技能形状和命中反馈清晰，而不是堆叠粒子数量。
- 特效应服务于俯视角战斗可读性：颜色、轮廓、持续时间和范围提示必须清楚。
- 火、冰、雷等技能应建立统一的颜色与形状语言，避免每个技能像来自不同游戏。
- 特效停止后及时停止发射并释放不再使用的粒子系统资源；GPU 粒子完全结束时需正确 dispose。

## 4. 分类筛选建议

### 4.1 模型与环境资源筛选建议

按首张森林主题地图（暂定名 Shadowgrove，待阶段1确认）和当前开发阶段排序：

1. **优先评估 KayKit Forest Nature Pack：** 与森林地图直接相关，免费版本已有较多环境模型，页面明确标注 CC0。

以上只是调研优先级，不是最终采用决定。免费素材适合早期验证，不代表最终美术资产必须使用这些素材。正式上线前应评估是否需要统一重制或定制模型。


### 4.2 PBR 材质筛选建议

针对首张森林主题地图（暂定名 Shadowgrove，待阶段1确认）：
1. **优先视觉筛选 Stylized Textures 与 3DTexel 免费 CC0 子集：** 风格化材质更接近卡通奇幻目标；逐项核对具体许可。

5. **移动端与浏览器优先控制尺寸：** 先验证 1K/2K 贴图表现，不因资源提供 4K 就默认使用 4K。

2. **需要高质量战斗和魔法音效时，再从 Sonniss GDC 合集中精挑：** 官方许可允许商业游戏，但文件量大且有独立再分发限制。
3. **环境音和特殊拟音可从 Freesound 补充：** 只挑 CC0 或 CC BY 文件，逐文件做许可记录。
4. **背景音乐可优先从 CC0 曲目开始：** Kenney Music Jingles、OpenGameArt 中明确 CC0 的单曲可作为候选；若使用 Incompetech 免费曲目，必须保留署名。
5. **Pixabay 可作为补充来源：** 使用平台自定义许可，不要把它标记为 CC0。
6. **不采用 NC 音频：** 项目目标包含商业发行可能性，非商业许可素材直接排除。

以上是资源来源筛选建议，不是最终曲目或音效采用决定。本阶段不下载、不安装、不集成任何音频文件。


### 4.4 特效方案筛选建议

1. **优先候选 Kenney Particle Pack：** CC0、80 个粒子纹理，适合搭建通用火花、魔法光点、轨迹和冲击效果。
2. **优先候选 Kenney Smoke Particles：** CC0、70 个烟雾/爆炸帧，适合爆炸、死亡消散和重击尘土。
3. **以 Babylon.js 原生粒子系统作为主要实现工具：** NPE 可辅助可视化搭建；根据设备能力选择 CPU/GPU 路径。
4. **特殊 3D 效果自行组合：** 魔法阵、护盾、闪电链和传送门需要网格、材质、动画和粒子组合；本轮没有确认一个许可清楚、可直接套用的完整 3D VFX 包。
5. **不改变当前技术路线：** 不因为某个特效资源面向 Unity/Unreal 就引入额外引擎或插件；先评估能否通过通用纹理/模型格式在 Babylon.js 使用。

本轮仅做资源与官方技术文档调研，不下载、安装或集成资源，不创建游戏代码。
