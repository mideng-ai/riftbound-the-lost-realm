# GAME_DESIGN_PRINCIPLES — 游戏设计原则

> **版本：** v1.1（五文档统一修订版）
> **更新日期：** 2026-11-11
> **状态：** 阶段0
> **重要说明：** 本文档依据项目总指令中确定的设计考量（四大支柱 + 九项设计要求）整理。凡涉及尚未经用户拍板的具体机制，本文只描述原则方向并标注「待确认」，不把草案当作已确定规则；具体机制决策统一记录于 DECISIONS_LOG.md。
> **检查标记约定：** 每条原则末尾给出可用于验收的检查标准（Check），供阶段4–6验收使用。

> **总规则（Check 的性质）：** 本文件中的 Check 是设计验证标准，而非必须机械执行的数值指标。如果严格满足某项标准会损害核心游戏体验，开发者应记录原因、提出替代方案，由项目负责人决定是否调整。

## 一、目标和即时小目标

### 原则 1.1：玩家永远知道「现在该干什么」（即时小目标）

- **原则说明：** 任意时刻，玩家面前都应存在一个清晰、可在数秒到数十秒内完成的小目标：一个发光的容器、一只可见的怪物、一个指路的方向标。
- **对玩家体验的意义：** 消除「漫无目的」感，尤其在俯视角 + 单局短时长的结构下，玩家迷失 = 无聊 = 流失。
- **在 Riftbound 中的应用：** 地图内放置明确的兴趣点（搜刮点、怪物巢、撤离点），拾取物和敌人使用高对比视觉引导；HUD 提供当前目标提示（具体引导形式待确认）。
- **Check：** 新玩家试玩任意 1 分钟片段，能说出「我刚才/现在想做什么」；地图上多数位置在短时间内（约 5 秒量级）可见至少一个潜在目标（参考标准：以探索体验不被「漫无目的」感破坏为准，允许局部例外）。

### 原则 1.2：30 秒微循环（微观节奏）

- **原则说明：** 每 30 秒左右应完成一次完整的微循环：遭遇 → 行动（战斗/搜刮）→ 反馈（掉落/收益/位置变化）。这是一局内最细粒度的「付出→回报」单元。**30 秒微循环是节奏参考，不代表每 30 秒必须掉落装备或资源。**
- **对玩家体验的意义：** 持续的短期奖励流维持心流，避免长段空窗期；每 30 秒都有理由继续。
- **在 Riftbound 中的应用：** 敌人密度与搜刮点间距按 30 秒节奏校准；每次遭遇都应有可感知的产出（战利品、金币、信息、通路）。密度数值 **待确认**，在阶段1/4 调校。
- **Check：** 实测录像抽样，任意连续 60 秒内至少出现 2 次明确收益事件（收益形式不限：掉落、信息、通路推进等）；无长时间连续「无事件」段落（具体容忍时长在阶段4调校确定，探索开荒期允许例外并单独验证）。

### 原则 1.3：5–15 分钟短期目标（局内目标）

- **原则说明：** 单局整体是一个 10–15 分钟的短期目标容器（项目确定值）：装满背包 → 达到满意收益 → 成功撤离。局内应允许玩家自己拆解出 3–5 个子目标（先搜哪个区、要不要打 Boss、何时撤）。
- **对玩家体验的意义：** 一局是一个完整可完成的「故事」，达成撤离带来闭环满足感；子目标给予玩家自主决策空间。
- **在 Riftbound 中的应用：** 搜刮容量、地图纵深、撤离点布局共同构成天然子目标链；撤离时机由玩家决定（原则见「风险与奖励」）。
- **Check：** 实测单局时长中位数落在 10–15 分钟；玩家在局内做出至少 3 次有意义的路线/时点决策（录像复盘可指认）。

### 原则 1.4：单局循环与长期成长目标分离

- **原则说明：** 局内追求的是战利品与生存；局外（营地）追求的是装备成长与能力解锁。两个循环目标明确分开，互不稀释：局内紧张感不应被复杂局外系统打断，局外成长不应让局内变成无脑碾压。
- **对玩家体验的意义：** 「这一局我打得很爽」和「这周我变强了」是两种满足感，分别供给不同动机玩家。
- **在 Riftbound 中的应用：** 局内界面只保留战斗必要信息；成长/构筑操作全部收进营地；营地成长方式 **待确认**（见 DECISIONS_LOG.md）。长期成长须避免把难度曲线压平。
- **Check：** 局内不存在任何需要「停下来读长文本/做构筑决策」的界面；营地操作平均一次会话 < 3 分钟；成长后旧内容仍有威胁感（难度曲线抽查）。

## 二、玩家反馈

### 原则 2.1：所有操作必须有即时反馈

- **原则说明：** 每个玩家输入都应得到及时的视觉或听觉回应；每个游戏事件（命中、受击、拾取、升级、危险预警）都有明确的多通道反馈。**输入响应、视觉反馈、完整动画应区分对待：** 输入响应要求最严格（100 毫秒级），关键视觉反馈紧随其后，完整动画表现可以更长——不得将所有反馈统一套用 100ms 要求。
- **对玩家体验的意义：** 反馈是「游戏手感」的底层；无反馈的操作让玩家失去控制感和爽感。
- **在 Riftbound 中的应用：** 施法有起手特效与音效，命中有点击反馈，受击有屏幕反馈（受击方向指示、画面微震——强度待确认），拾取有音效与飞入动画。
- **Check：** 操作→**输入响应**延迟实测 < 100ms（输入采样到首帧表现）；关键事件的反馈按类型分级验收（输入响应 / 关键视觉反馈 / 完整动画各自设定标准）；关键事件反馈清单逐项验收（施法/命中/受击/拾取/撤离/死亡）。

### 原则 2.2：反馈清晰不噪音

- **原则说明：** 反馈要能区分重要性：致命威胁 > 普通伤害 > 环境信息。反馈叠加时不能让玩家漏掉最重要的信号。
- **对玩家体验的意义：** 搜打撤游戏中「漏看危险」直接导致不公平死亡，破坏信任。
- **在 Riftbound 中的应用：** 高威胁事件（Boss 技能、包围预警）使用独占的视听通道；常规事件反馈降级处理。具体预警形式待确认。
- **Check：** 测试中故意同时触发「拾取 + 怪物攻击」，玩家必须能先注意到攻击；重要预警的漏看率在测试中可接受。

## 三、核心玩法循环

### 原则 3.1：四大支柱是唯一的循环骨架

- **原则说明：** 战斗爽感、探索搜刮、撤离决策、装备成长——单局循环的每一段都必须至少服务一个支柱，且四者在整体内容中比重均衡。
- **对玩家体验的意义：** 防止游戏滑向单一玩法（纯割草或纯跑图），保持「搜打撤」的独特张力。
- **在 Riftbound 中的应用：** 单局流程固定为：进入 → 探索/搜刮（支柱2）→ 战斗（支柱1）→ 撤离决策（支柱3）→ 局外成长（支柱4）。任何新系统先过支柱检验。
- **Check：** 逐个新功能能指认所服务的支柱；单局录像中四个支柱各有可辨识的玩法段落。

### 原则 3.2：循环每一圈都有增量

- **原则说明：** 局内推进（时间、深度、贪婪度）应持续提高收益与风险；局外推进应持续提供新目标，直到首版内容上限。
- **对玩家体验的意义：** 「再来一局」的动力来自增量感：这一局比上一局多了什么。
- **在 Riftbound 中的应用：** 深入地图 = 更高稀有度掉落 + 更高威胁；跨局 = 更好装备解锁更深内容。增量耗尽点 = 首版内容边界（见 GAME_SCOPE.md）。
- **Check：** 相邻深度区域的掉落稀有度/威胁值呈单调上升；首版内容边界明确可测。

## 四、战斗和操作

### 原则 4.1：爽感优先于拟真

- **原则说明：** 战斗手感（响应、命中反馈、节奏）优先于物理拟真和数值复杂。宁可简单但要「打到有感觉」。
- **对玩家体验的意义：** 支柱1（有爽感的魔法战斗）的直接要求。
- **在 Riftbound 中的应用：** 攻击判定宽松对玩家有利、命中反馈强烈、技能动画紧凑。具体法术手感参数在阶段4调校。
- **Check：** 用户与测试者主观评价「打击感达标」；命中率测试中玩家可感知命中率显著高于严格判定。

### 原则 4.2：操作方案双端一等公民

- **原则说明：** PC（键鼠）与手机（触屏）都不是「移植端」，操作方案必须双端同时设计、同时验收。具体操作布局 **待确认**（见 DECISIONS_LOG.md）。
- **对玩家体验的意义：** 首发平台即双端；任何一端体验明显劣化都会砍掉一半受众。
- **在 Riftbound 中的应用：** 输入抽象层统一两端指令；技能数量与 UI 布局以触屏可用性为约束上限。
- **Check：** 同一玩法功能双端均可在 10 分钟内学会；触屏端完成一局不出现误触导致的不公平死亡（测试记录）。

### 原则 4.3：深度来自选择，不来自复杂

- **原则说明：** 战斗深度通过「什么时机用什么技能、走位到哪、打不打」的选择产生，而不是通过增加按键数量和操作链复杂度。
- **对玩家体验的意义：** 触屏端按键空间有限；选择型深度对新手友好、对高手有上限。
- **在 Riftbound 中的应用：** 普通攻击 + 少量技能（数量待确认）+ 闪避/走位构成决策空间；技能间形成组合关系（如控制→爆发）。
- **Check：** 高手玩家与新手的操作差异体现在决策（录像可指认）而非按键速度；技能总数不超过触屏可用布局上限。

## 五、风险与奖励

### 原则 5.1：贪婪必须付出可见代价

- **原则说明：** 多留一分钟、多进一层、多打一个 Boss，收益提高的同时威胁必须可见地提高。玩家在下注前能看清赔率。
- **对玩家体验的意义：** 支柱3（撤离决策）的张力来源；「看得懂的风险」才有决策，不透明的死亡只会带来挫败。
- **在 Riftbound 中的应用：** 深度与收益/威胁挂钩（原则3.2）；撤离窗口有明确时限或条件（具体规则待确认）；危险信号（声音、视觉、UI）先行于实际威胁。
- **Check：** 死亡原因应尽可能让玩家理解（多数死亡可归因：玩家或测试者能说出主要失误或贪婪点）；**允许多个因素共同造成死亡**，不要求每次死亡都能归因到单一原因；收益-风险曲线单调且可感知。

### 原则 5.2：死亡有惩罚但不是毁灭

- **原则说明：** 死亡惩罚要有分量（否则撤离无意义），但不能摧毁玩家已积累的成长（否则劝退）。具体惩罚规则 **待确认**（见 DECISIONS_LOG.md）。
- **对玩家体验的意义：** 惩罚太轻 → 撤离决策消失；太重 → 玩家提前撤离或弃游。这是搜打撤的生死平衡点。
- **在 Riftbound 中的应用：** 惩罚对象限定于本局所得（携带未撤离的战利品），长期成长资产（营地、已撤离装备）原则上不因单次死亡清零——最终以用户确认的规则为准。
- **Check：** 连续死亡 3 次的玩家仍保留可感知的进度；单局死亡后仍有「再来一局」的意愿（测试访谈）。

### 原则 5.3：撤离是玩家主动的胜利动作

- **原则说明：** 撤离不是「逃跑」的负面表述，而是主动选择的胜利条件；成功撤离应有明确的正反馈仪式感。
- **对玩家体验的意义：** 把紧张感转化为成就感，鼓励玩家重复体验「带着满满战利品撤出」的核心爽点。
- **在 Riftbound 中的应用：** 撤离成功有专属结算表现（音效、结算画面展示本局收获）。
- **Check：** 撤离成功结算清晰展示本局收益对比；测试者对撤离瞬间的情绪反馈为正向。

## 六、地图与探索

### 原则 6.1：探索必须有回报

- **原则说明：** 探索路线应通过战利品、挑战、捷径、隐藏区域、环境故事等方式产生价值，**不要求每个角落都有物品**。绝不允许「走了半天什么都没有」的长段空回报。
- **对玩家体验的意义：** 支柱2（有价值的探索和搜刮）；无回报探索会训练玩家走直线，毁掉地图价值。
- **在 Riftbound 中的应用：** 兴趣点按密度规则布置（密度数值待确认）；探索奖励与风险挂钩（原则5.1）；回报形式多样化（不只物品掉落）。
- **Check：** 地图抽样检查：任意分支路线存在至少一种价值来源（战利品/挑战/捷径/隐藏区域/环境故事之一即可）；「长段零回报路线」的比例低于设定阈值（阈值在阶段1定稿）。

### 原则 6.2：地图可读，迷路可控

- **原则说明：** 俯视角下玩家应能快速建立空间认知：地标清晰、区域风格有区分度、必要时提供定位辅助。
- **对玩家体验的意义：** 单局 10–15 分钟，迷路 5 分钟等于毁掉一局。
- **在 Riftbound 中的应用：** 区域视觉差异化、标志性大地标、小地图或指路辅助（形式待确认）。
- **Check：** 测试中玩家从任意点到撤离点平均无过度绕路；新玩家迷路求助率低于阈值。

### 原则 6.3：地图生成方式一经确认即冻结为技术约束

- **原则说明：** 程序生成与手工设计各有利弊（见 DECISIONS_LOG.md 待确认项），确认后地图系统的所有设计与实现都按该方向推进，不做双轨。
- **对玩家体验的意义：** 生成方式决定重复可玩性与内容成本，是地图一切设计的地基。
- **在 Riftbound 中的应用：** 无论何种方式，首版保证「单局内空间可读 + 跨局有变化感」两个目标。
- **Check：** 连续 10 局布局不重样（若为生成式）或内容点布局有可感知变化（若为手工式）；空间可读性通过原则6.2检查。

## 七、怪物与 Boss

### 原则 7.1：怪物行为可读、可学习

- **原则说明：** 每种怪物有清晰的外形识别度和可预判的行为模式：玩家被击中后应能说出「下次我会躲/先手/绕开」。
- **对玩家体验的意义：** 公平感与成长感来自「我学会了打它」；不可读的威胁 = 随机挫败。
- **在 Riftbound 中的应用：** 怪物外形与威胁等级挂钩（越危险越显眼）；每种怪物攻击有前摇提示。
- **Check：** 新怪物首遇死亡率不显著高于同类；测试者能复述每种怪物的应对方式。

### 原则 7.2：威胁分层，而非单纯堆数值

- **原则说明：** 怪物难度通过机制差异化实现（近战压力、远程骚扰、范围威胁、控制等），Boss 是机制考试的检查点，不是血量倍增器。
- **对玩家体验的意义：** 机制分层让战斗保持新鲜，Boss 战成为单局的高潮。
- **在 Riftbound 中的应用：** 首版怪物阵容覆盖多种威胁类型（首版目标数量见 GAME_SCOPE.md，待阶段1最终确认）；Boss 具备必须应对的机制点，**机制数量应结合首版规模和实际测试确定**（当前参考范围 2–3 个，非硬性指标）。
- **Check：** 不同怪物组合改变玩家的走位与技能使用（录像可指认）；Boss 战中玩家做出针对性应对（应对次数以实际测试体验为准，不做机械指标）。

## 八、装备和成长

### 原则 8.1：每件装备都改变玩法，不只是改数字

- **原则说明：** 装备的价值梯度 = 稀有度数字提升之上，必须有「玩法变化」维度：新的攻击方式、新的被动、构筑方向。
- **对玩家体验的意义：** 支柱4（有意义的装备成长）；纯数值装备让搜刮变成看数字，失去构筑乐趣。
- **在 Riftbound 中的应用：** 装备组合方式 **待确认**（见 DECISIONS_LOG.md）；构筑数量按统一口径执行：首版最低要求至少 2 种玩法明显不同的构筑，目标争取实现 3 种，不得为满足数量而牺牲玩法质量（同 GAME_SCOPE.md）。
- **Check：** 两种构筑在录像中肉眼可辨差异（技能形态/节奏/走位方式）；高稀有度装备的掉落能引发玩家的兴奋反应。

### 原则 8.2：成长曲线平滑，无断崖

- **原则说明：** 局外成长持续但克制：每小时的游玩都能感到变强，但任何单一获取不应让现有内容瞬间失去挑战。
- **对玩家体验的意义：** 防止「毕业即弃游」和「卡关劝退」两种曲线病。
- **在 Riftbound 中的应用：** 营地成长方式待确认后，数值曲线按此原则校准；难度随成长段位有对应的内容梯度。
- **Check：** 任一时间点的玩家都能找到威胁适度的内容；装备提升实测感知间隔（多久有一次「变强了」时刻）符合设定。

### 原则 8.3：搜刮的期待感来自稀有度结构

- **原则说明：** 掉落系统用清晰的稀有度层级制造「开箱时刻」的期待感；高稀有必须可见、可期待、可追求。
- **对玩家体验的意义：** 搜刮的心理奖励机制；稀有度是撤离决策中的「赌注单位」。
- **在 Riftbound 中的应用：** 稀有度分层（具体几档待确认）在视觉上强区分；高稀有度有专属掉落表现。
- **Check：** 稀有度视觉区分测试通过（一眼可辨）；各稀有度实际掉率与数值表一致（不虚标）。

---

## 九、游戏节奏

### 原则 9.1：紧张—释放交替

- **原则说明：** 单局内高压段（强敌、Boss、撤离冲刺）与低压段（搜刮、整备）交替出现，不持续高压也不持续平淡。
- **对玩家体验的意义：** 紧张感需要释放才有对比；持续高压在触屏端尤其导致疲劳。
- **在 Riftbound 中的应用：** 地图分区承担节奏功能（外围缓冲区 → 中部遭遇区 → 深部高压区 → 撤离冲刺）。
- **Check：** 单局节奏图（按事件强度绘制）呈波浪形；无超过预设时长的高压连续段。

### 原则 9.2：难度曲线服务留存

- **原则说明：** 前几局以「学会核心循环」为唯一难度目标，允许玩家赢；随成长逐步引入真实威胁。难度从不通过不公平手段（看不见的攻击、无效反馈）制造。
- **对玩家体验的意义：** 阶段6验收的「新玩家能完成首局」依赖此原则；不公平难度是留存杀手。
- **在 Riftbound 中的应用：** 初始难度参数低于稳态；所有威胁均遵循可读性原则（7.1、2.2）。
- **Check：** 新玩家首局完成率达标；死亡原因理解度测试通过（同 5.1：死亡原因应尽可能让玩家理解，允许多因素共同作用；不可接受的是「因信息缺失而无法理解」的死亡）。

## 十、新手体验

### 原则 10.1：首局即完整循环

- **原则说明：** 新手引导的目标是让玩家在第一局内经历完整的「搜打撤」循环并成功撤离——先给完整的爽感，再谈进阶。
- **对玩家体验的意义：** 搜打撤的核心魅力（撤离瞬间）必须在前 15 分钟内交付一次。
- **在 Riftbound 中的应用：** 引导方式待确认（渐进提示 or 首局特殊布局）；引导覆盖移动、攻击、拾取、撤离四个动作。
- **Check：** 无外部说明的新玩家首局撤离成功率达标；四项核心动作在首局内全部自然完成。

### 原则 10.2：引导教思考，不教背板

- **原则说明：** 引导传达的是「为什么」（撤离才能保住战利品、深入更危险也更值钱），而不是固定操作序列。
- **对玩家体验的意义：** 玩家理解动机后才能做出自主决策——这是本作的乐趣核心。
- **在 Riftbound 中的应用：** 关键规则（死亡惩罚、撤离）在首次相关场景中即时说明，而非开局长文轰炸。
- **Check：** 引导后玩家能复述「为什么要撤离」「死了会怎样」；引导文字总量受控。

---

## 十一、UI 与可读性

### 原则 11.1：俯视角可读性是硬约束

- **原则说明：** 敌我、技能范围、拾取物、危险区域在俯视角下必须一眼可辨。可读性问题按 Bug 级别处理，不是美术偏好问题。
- **对玩家体验的意义：** 俯视角缩小了视觉信息量，可读性直接决定公平性。
- **在 Riftbound 中的应用：** 敌我配色强对比、技能范围地面指示、危险区域预警色、拾取物发光轮廓（具体规范在阶段2/5定稿）。
- **Check：** 截图测试：随机截图可立即分辨敌/我/物/危险区；小屏幕（手机）上同样通过。

### 原则 11.2：双端 UI 一次设计

- **原则说明：** 所有 UI 以「手机小屏 + 触控」为约束基线设计，PC 端享受同等体验；杜绝 PC 先行、手机凑合。
- **对玩家体验的意义：** 触屏端是首发平台之一；小屏约束反而倒逼信息层级清晰。
- **在 Riftbound 中的应用：** HUD 极简（原则1.4），构筑界面收进营地；按钮热区满足触屏标准。
- **Check：** 手机主流分辨率下无遮挡、无过小热区；两端信息一致性检查通过。

---

## 十二、音效与视觉表现

### 原则 12.1：音效是反馈系统的一半

- **原则说明：** 关键事件必须配音效（施法、命中、受击、拾取、稀有掉落、撤离、危险预警）；音效与视觉反馈互补而非重复装饰。
- **对玩家体验的意义：** 触屏端注意力集中在手指区域，音效承担大量屏幕外信息（原则2.2）。
- **在 Riftbound 中的应用：** 危险预警优先给声音通道；稀有掉落用专属音效强化「开箱时刻」（8.3）。**静音情况下，危险预警仍必须有足够清晰的视觉提示**，不得只依赖音频通道。
- **Check：** 关键事件音效清单逐项验收；静音状态下危险预警仍有足够清晰的视觉提示，预警事件遗漏率在可接受范围（视觉通道兜底有效）。

### 原则 12.2：美术鲜艳卡通，但不牺牲功能

- **原则说明：** 美术在鲜艳卡通的大方向下服务玩法功能：特效醒目服务于战斗反馈，色彩服务于可读性。
- **对玩家体验的意义：** 风格是辨识度，功能是底线；两者冲突时功能优先。
- **在 Riftbound 中的应用：** 法术特效在鲜艳与可读间取平衡（特效不遮挡战场）；UI 风格与卡通渲染统一。
- **Check：** 特效密集场景（多怪 + 多技能）下敌我识别仍通过 11.1 检查；美术与功能冲突以功能裁决并有记录。

## 十三、测试和平衡

### 原则 13.1：不虚报测试结果

- **原则说明：** 一切测试结论必须有真实运行记录支撑：明确测试了什么、结果如何、什么没测。绝不虚构通过。
- **对玩家体验的意义：** 这是项目总指令的红线；虚报导致问题带病上线，最终伤害玩家。
- **在 Riftbound 中的应用：** 每阶段产出测试记录（ROADMAP 各阶段验收标准已内嵌此要求）。
- **Check：** 抽查任意测试结论可追溯到运行记录；未测项均有明示。

### 原则 13.2：平衡基于数据与可归因反馈

- **原则说明：** 数值调整依据实测数据（击杀率、撤离率、死亡地点、构筑使用率）与可归因的玩家反馈，不凭感觉拍脑袋。
- **对玩家体验的意义：** 平衡好的游戏里，玩家的每次选择都「有道理」；平衡差则 choices 退化成正确答案背诵。
- **在 Riftbound 中的应用：** 阶段4起建立平衡记录；关键指标（撤离率、构筑分布、单局时长）纳入常规观测。
- **Check：** 每次数值调整有依据记录；构筑使用率分布在目标区间（无单一构筑垄断）。

---

## 十四、长期运营

### 原则 14.1：更新以加法为主，契约可审慎变更

- **原则说明：** 运营期更新优先以新增内容（怪物、装备、地图）扩展；**核心规则可以在项目负责人批准后调整，并记录变更原因**，但避免无审批地重写已确定的操作、惩罚、成长规则——那些是玩家的「肌肉记忆契约」。
- **对玩家体验的意义：** 玩家对规则稳定性有信任；频繁无审批改核心规则消耗信任与学习成本，但一刀切禁止变更也会让规则缺陷无法修正。
- **在 Riftbound 中的应用：** 核心规则变更须项目负责人批准并公告，同时在 DECISIONS_LOG.md 记录变更原因；更新路线以四大支柱为筛选标准（GAME_SCOPE.md 流程）。
- **Check：** 每次更新能指认新增/调整内容及其支柱归属；所有核心规则变更均有批准记录与原因记录（DECISIONS_LOG.md）。

### 原则 14.2：运营节奏可持续

- **原则说明：** 更新计划量力而行：小步稳定优于大跃进；每次更新前确保上一版稳定。
- **对玩家体验的意义：** 稳定可玩的旧内容 > 不稳定的新内容。
- **在 Riftbound 中的应用：** 更新 backlog 经用户批准后执行（ROADMAP 阶段7）；热修优先于内容更新。
- **Check：** 每次更新发布前回归测试通过；更新间隔与内容量符合 backlog 承诺。
