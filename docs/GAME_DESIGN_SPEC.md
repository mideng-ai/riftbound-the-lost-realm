## 3. 单局核心循环

### 3.1 本轮已明确的体验方向

状态：**体验方向已由负责人明确选择；不等于具体玩法规则已确定。**

- **整体节奏：探索与紧张并重。** 前段应给玩家观察环境、熟悉局势和探索搜刮的空间；随着玩家主动深入、接近高价值目标或选择高风险遭遇，紧张感逐步上升。
- **四大体验均衡：** 魔法战斗、探索搜刮、撤离风险决策、装备成长均应在一局中有存在感，不把整局做成单纯刷怪、单纯开箱或单纯逃生。
- 四大支柱是设计权重与体验目标，不要求每一分钟平均分配，也不应为追求形式上的平均而牺牲节奏。

### 3.2 单局时长口径提案

状态：**提案/待确认。**

- 建议将 10–15 分钟定义为「从进入地图开始，到撤离/死亡结算为止」的战局时长。
- 营地整备放在战局外，不计入这 10–15 分钟；进入地图前的选装与整理应保持轻量，避免准备阶段拖慢核心循环。
- 以上是计时口径建议，尚未成为 D-006 的新增细则；若负责人希望将营地整备也计入单局时长，需要再调整节奏预算。

### 3.3 建议的战局节奏分段

状态：**提案/暂定节奏预算，不是硬性计时脚本。** 玩家可以在适当时机提前撤离；各阶段的遭遇数量、掉落数量和具体事件均待后续设计与测试。

| 战局时间 | 阶段 | 体验目标与建议内容 |
|---|---|---|
| 0:00–1:30 | 进入与观察 | 让玩家快速读懂周围环境、主要方向和初步威胁；给出低压力的移动、观察与首次探索机会。 |
| 1:30–4:00 | 初次探索与战斗 | 安排早期普通敌人或轻量遭遇，让玩家使用基础战斗能力；附近应存在可发现的资源或奖励，让战斗与探索互相推动。 |
| 4:00–7:00 | 探索分支与奖励 | 鼓励玩家在相对安全的推进路线和更有吸引力的支线目标之间作选择；通过宝箱、资源点或事件形成搜刮期待。 |
| 7:00–10:00 | 风险上升与强遭遇 | 让深入区域的威胁更明显，可安排精英敌人或更复杂的战斗情境；更高价值的机会应伴随可理解的风险。 |
| 10:00–12:00 | 价值评估与撤离抉择 | 玩家结合已获得的战利品、当前生存状态和继续探索的预期收益，判断是否结束本局。此时应让撤离成为有意义的主动选择。 |
| 12:00–15:00 | 可选的高风险目标与收尾 | 仍愿冒险的玩家可以挑战更深区域或高价值目标，再寻找机会结束本局；不应强迫每局都挑战 Boss 或走完整个时间段。 |

节奏说明：

1. 上表是目标体验的时间参考，不要求每局严格按分钟触发事件。
2. 不应把 Boss 设为每局必打的强制终点；Boss 出现频率、触发方式和是否属于可选目标仍待设计。
3. 撤离不应被设计成只能在最后几分钟考虑的按钮。建议玩家在战局中逐步形成「现在已获得什么、继续冒险还可能得到什么、当前风险是否值得」的判断；撤离点的开放时机和具体操作仍待 D-202、D-203 讨论。
4. 若玩家在较早阶段已经获得满意收获，允许其选择较短战局；若玩家主动承担更高风险，则可将战局延伸至 12–15 分钟区间。
5. 不建议仅靠全局倒计时强制制造紧张感。更优先考虑用区域危险程度、遭遇强度、路线选择和玩家当前状态逐步构成压力；是否加入时间压力机制尚未决定。

### 3.4 完整循环节点

状态：**流程框架提案；具体系统规则待确认。**

1. **营地整备（战局外）：** 玩家查看已有装备与资源，选择本局准备使用的配置。整备内容和操作深度受 D-205、D-206 影响，暂不规定槽位、升级或消耗规则。
2. **进入裂隙：** 玩家进入本局地图，快速识别周围环境、可探索方向和当前威胁。
3. **探索与选择路线：** 玩家寻找资源、宝箱、事件或通往高风险区域的路线；探索应提供选择，而不是只沿唯一通道前进。地图的实际生成方式与布局由 D-203 决定。
4. **遭遇与魔法战斗：** 玩家根据敌人行为选择攻击、技能和走位方式。战斗应有明确的威胁提示、命中反馈和战后喘息空间；具体操作、技能和防御机制分别由 D-201、D-204 讨论。
5. **搜刮与构筑价值：** 玩家获得装备或资源，并逐步增加本局收获及跨局成长可能性。搜刮物品如何影响即时构筑、装备槽位、词条和资源用途，均由 D-205、D-206 决定。
6. **评估风险并决定去留：** 玩家综合当前状态、已有收获、前方目标和撤离成本，选择继续探索或尝试撤离。该节点是支柱2与支柱3的主要交汇点。
7. **撤离成功或角色死亡：** 本局进入结束状态。成功与失败的物品处理、死亡损失和保留规则必须遵照之后确认的 D-202，不在本提案中预设。
8. **结算与返回营地：** 展示本局结果，处理可保留的战利品，并让玩家进行下一局整备。局外经济、营地升级和长期成长由 D-206 决定；持久化方案 D-207 留到阶段2。

### 3.5 四大支柱在单局中的体现

状态：**体验目标提案。**

| 玩法支柱 | 单局中应提供的体验 | 避免出现的问题 |
|---|---|---|
| 魔法战斗爽感 | 有节奏的普通遭遇、具有辨识度的强敌，以及清晰的施法、命中和击败反馈 | 全程无差别刷怪，或战斗只成为拾取奖励的门槛 |
| 探索与搜刮价值 | 可读的环境线索、值得发现的兴趣点、路线选择和有差异的奖励机会 | 宝箱和资源平均散布，探索不产生判断或惊喜 |
| 撤离决策紧张感 | 收获越有价值，继续深入与安全结束之间的取舍越有意义 | 玩家没有理由提前撤离，或只因突然出现的强制倒计时而撤离 |
| 装备成长意义 | 本局发现的装备与资源能让玩家期待下一局的配置变化或长期成长 | 掉落只有数值高低，没有构筑意义；具体装备机制仍须 D-205、D-206 确认 |

### 3.6 节奏与体验检查标准

状态：**用于后续评估的设计检查项，不是数值验收门槛。**

- 前段是否给了玩家足够时间观察、移动、探索和理解威胁？
- 战斗是否有变化和间隔，而不是从进入地图起持续无休止地受袭？
- 玩家是否至少有机会作出有意义的探索/奖励选择？
- 深入高风险区域是否能让玩家理解「风险增加的原因」及潜在收益？
- 玩家是否会基于自己的收获和状态主动思考撤离，而不是只跟随系统倒计时？
- 战利品是否能连接到有意义的装备选择或跨局成长？具体连接方式待 D-205、D-206 决定。
- 如果玩家在 10 分钟左右结束本局，是否仍能获得完整、有收获感的体验？如果玩家继续到 15 分钟，是否能感受到额外风险与额外价值？

### 3.7 仍待确认的规则边界

- D-202：死亡惩罚、战利品保留/损失、撤离触发及流程。
- D-203：地图生成方式、地图结构与撤离点分布。
- D-204：闪避与防御机制。
- D-205：装备槽位、稀有度、词条、局内装备与构筑机制。
- D-206：营地成长、资源用途和局外经济。
- D-208：世界观细节与角色设定。

- Boss 是否每局出现、是否必打，以及区域危险是否随时间变化：均为待设计问题。

## 4. 操作与战斗设计

### 4.1 开发与验证优先顺序

状态：**已确认开发优先顺序；不改变双平台首发目标。**

- 项目首发平台仍为 PC 浏览器与手机浏览器，依据 D-004；手机优先不代表取消、缩减或降低 PC 版本的首发要求。
- **开发顺序：先完成手机端核心体验，再开发和适配 PC 端。**
- 阶段2仍须从技术架构层面考虑双平台：建立平台无关的游戏逻辑与输入接口，并进行必要的浏览器/设备技术验证；但不要求在阶段2完成 PC 端完整操作与 UI。
- **设计层面仍须同步考虑 PC 与手机都是首发平台**，避免手机操作方案依赖无法映射到键鼠的专属战斗规则；手机优先指开发与原型验证顺序，不代表 PC 操作需求可以等到最后才被考虑。
- 阶段3 M1 优先以手机浏览器为主要可玩验证目标，先跑通移动、战斗、探索、搜刮、撤离和结算的核心闭环。
- 后续实现顺序为先完善手机端核心体验，再接入 PC 键鼠输入与桌面 UI 布局；阶段6须完成双平台回归与验收。
- 不得采用「先写一套手机专用逻辑，之后复制一套 PC 逻辑」的方式。移动、战斗、技能、敌人、掉落和结算等规则应共享；平台差异集中在输入适配、UI 布局和显示交互层。

### 4.2 双端操作的共同原则

状态：**普通攻击自动化方向已确认；双端具体输入映射仍待 D-201 完成。**

1. PC 与手机共享同一套战斗规则；普通攻击在两端均自动触发并自动判断攻击方向，不同平台主要改变移动输入、技能输入与界面布局。
2. 手机端优先降低持续操作负担，让玩家把注意力放在移动、路线选择、威胁判断和技能时机上。
3. **提案/待确认：** 建议允许玩家移动中进行普通攻击；该规则仍需与 D-201 的攻击动作、自动选敌和触屏操作一起确认。技能是否允许移动中施放，按技能类型进一步设计。
4. 自动普通攻击必须有可理解、可预期的规则和反馈；首个小版本的特殊技能由玩家手动施放。
5. 手机 UI 以单手/双手拇指可触达区域为约束，同时注意屏幕边缘、浏览器系统手势区域和战场可视面积。
6. PC 端仍需映射到同一套核心战斗规则；具体键鼠操作暂不在本轮冻结。

### 4.3 手机触屏操作方向（负责人已明确基础方向）

状态：**手机左手移动、双平台自动普通攻击与首版手动技能方向已明确；具体控件参数和技能输入仍待设计。**

负责人明确的手机操作规则：

1. **左手控制移动：** 左侧虚拟摇杆或等效触控区域负责角色移动；固定/动态摇杆形式、尺寸与灵敏度留待原型验证。
2. **普通攻击自动触发：** 玩家不需要持续点击普攻按钮；满足攻击条件时角色自动进行普通攻击。
3. **攻击方向自动判断：** 系统根据已确认的选敌规则决定普通攻击朝向。
4. **首个小版本技能仅手动施放：** 两种特殊技能均由玩家主动点击按钮施放；首版不实现自动施法、逐技能自动/手动切换或相关模式 UI。自动技能在小版本完成后再研究。
5. **双平台共享战斗规则：** 上述普通攻击规则同时适用于手机与 PC；平台差异集中在移动输入、技能输入和 UI 布局。

手机端布局建议（提案，待原型验证）：

| 区域 | 功能方向 | 状态 |
|---|---|---|
| 左下区域 | 移动摇杆/移动触控区 | 操作职责已确认；控件形式待测试 |
| 右下或右侧 | 两个手动技能按钮 | 首版手动技能范围已确认；具体位置、尺寸与反馈待测试 |
| 屏幕中央 | 角色、敌人、战斗与环境信息 | 以保持视野清晰为目标 |
| HUD 信息区 | 生命、技能冷却及必要提示 | 具体信息层级待 UI 设计 |

补充规则：

- **没有有效敌人时停止普通攻击：** 不空放普攻；出现有效目标后自动恢复。
- **PC 端同样采用自动普通攻击：** PC 与手机共享自动普攻和自动判断方向规则；PC 移动、技能键位与 UI 映射仍待设计。
- 首版技能的点击即施放、按住瞄准或指定落点等交互，须根据两种技能的最终效果分别确定；不预设所有技能使用同一种瞄准方式。
- 技能施放失败（例如冷却中、资源不足或目标/落点无效）应提供明确反馈；具体失败条件依技能设计决定。

#### 4.3.1 自动攻击选敌：竞品研究与推荐方案

状态：**竞品事实为外部研究结果；推荐优先级为 AI 提案，待负责人确认。**

**竞品做法**

| 游戏 | 可查证的目标选择/自动攻击做法 | 对 Riftbound 的启示 |
|---|---|---|
| Diablo Immortal | 早期测试体验报道记载：普通攻击会自动瞄准最近敌人或玩家正在朝向的敌人，技能默认使用自动选择的目标。报道来自早期测试，不应当作当前版本所有职业的完整规则。 | 最近目标易懂；移动/朝向可间接影响目标选择。 |
| Brotato | 每件武器独立寻找其攻击范围内最近的敌人；没有有效目标时保持不攻击；其默认规则不按 Boss 或威胁等级加权。相关机制分析注明目标选择细节是基于观察归纳。 | 最近有效目标 + 无目标停火，是简洁稳定的基线。 |
| Vampire Survivors | 不同武器采用不同攻击模式：最近目标、角色朝向、随机目标、环绕或范围攻击；武器各自按冷却自动发动。 | 自动攻击不一定只有一种目标规则；不同技能/武器可以按效果选择适合的自动逻辑。 |
| Torchlight: Infinite | 自动技能支持按具体条件触发，例如附近有精英/Boss、生命值或能量护盾低于阈值等。 | 自动施法可以按技能职责建立明确触发条件，而不是不透明地随机释放。 |

**研究观察**

- 「最近的有效敌人」是多个自动攻击游戏采用的基础方式，优点是简单、可预测；缺点是可能把攻击浪费在普通小怪身上，而忽略远处精英/Boss。
- 「永远优先 Boss」也不是普遍共识。Villagers & Heroes 的小样本投票中，最近目标获得 56.5%，附近最强 Boss 获得 43.5%；该结果只作为偏好分歧的例子，不代表普遍玩家调查。
- Brotato 的分析明确指出，纯最近目标不考虑威胁或 Boss 权重，会出现远程武器把攻击打在普通敌人身上的情况。
- 自动技能与普通攻击可以采用不同规则：普通攻击偏向稳定持续输出；特殊技能更适合根据敌人群聚、精英/Boss 出现或玩家危险状态判断时机。

**Riftbound 已确认选敌规则：附近威胁优先 + 距离辅助（负责人确认，2026-11-12）**

负责人已明确认可该方案，作为普通攻击自动选敌的设计规则：

1. **候选筛选：** 只考虑存活、敌对、处于普通攻击有效范围内且攻击路径有效的敌人；具体视线与遮挡判定留待技术设计。
2. **第一优先级——即时威胁：** 正在攻击玩家、正在冲锋、正在施放针对玩家的危险技能，或已经贴近玩家构成直接威胁的敌人。若有多个，优先选择威胁更近/更迫切的一个。
3. **第二优先级——高威胁单位：** 当没有即时威胁目标时，考虑精英、Boss、远程施法者或能明显强化其他敌人的单位；但高威胁单位必须在合理距离内，不能为了攻击远处 Boss 而忽略近身敌人。
4. **第三优先级——普通目标：** 选择最近的其他有效敌人。
5. **目标稳定性：** 一旦选定目标，只要目标仍有效就尽量保持；只有目标死亡、离开有效范围、路径失效或出现明显更高优先级威胁时才切换，避免攻击方向频繁跳动。
6. **无有效目标：** 停止普通攻击，等待下一次出现有效目标后自动恢复。

该规则的核心是让普通攻击优先处理玩家眼前真正造成压力的威胁，同时保留最近目标规则的可预测性。优先级权重、目标保持时间及距离阈值仍需在阶段3原型中测试；本次确认的是选敌层级与行为原则，不代表相关数值已确定。

**自动技能时机建议（AI 提案，规则方向已确认、具体条件待确认）**

自动模式下由游戏系统按技能类型判断时机。可考虑的触发逻辑示例：

- 范围伤害技能：多个敌人聚集、或精英/Boss 与其他敌人处于有效范围时考虑施放。
- 单体爆发技能：优先用于高威胁精英/Boss，而不是随意浪费在普通小怪上。
- 防御/护盾/治疗类技能：玩家生命或防御状态达到危险条件，或即将承受明显攻击时考虑施放。
- 控制类技能：敌人正在包围、聚集或准备发动危险攻击时考虑施放。

以上是候选判断思路，不代表首版已有这些技能类别，也不代表任何阈值已经确定。自动模式须遵守技能冷却、资源消耗、目标有效性和技能自身限制；当条件不满足时不应强行施放。

### 4.5 普通攻击与特殊技能

手机端的基础方向已明确为「左手移动、普通攻击自动触发且攻击方向自动判断」；PC 端也已确认采用自动普通攻击与自动判断方向。首个小版本只实现手动技能施放；自动技能暂缓，待小版本完成后再研究。此前「每个技能独立设置自动/手动」及自动技能动态优先级属于后续设计讨论背景，不构成首版功能要求。攻击间隔、手动技能输入方式、移动中施法限制，以及 PC 移动/技能键位与 UI 映射仍待 D-201 后续设计确认。

#### 4.5.0 首个小版本的普通攻击方式

状态：**攻击类型与基本形态已由负责人确认；具体数值与表现细节待设计/原型验证。**

- **远程魔法法杖：** 普通攻击采用远程攻击。具体弹道表现（例如魔法弹或魔法箭）、射程、飞行速度、攻击间隔与命中效果仍待确认。
- **近距离魔法剑：** 普通攻击采用**扇形挥砍**。角色朝自动选定的有效目标方向挥剑，攻击判定覆盖角色前方的扇形区域；该形态可攻击前方范围内的多个敌人。负责人已确认采用 **B 方案：120° 扇形、中等攻击距离**，攻击节奏采用**标准挥砍，初始目标约每 1 秒发动一次**。上述角度与节奏作为首版初始设计目标，须通过原型试玩验证；中等攻击距离尚未换算为具体世界单位，实际距离、动作时长、伤害与命中反馈仍待设计和验证。
- 两种武器的普通攻击均沿用已确认的自动普通攻击与自动选敌原则；本次确认扇形挥砍形态，不代表上述参数已确定，也不代表特殊技能与武器之间存在绑定关系。


#### 4.5.1 自动技能（后续版本研究项，首个小版本不实现）

**当前开发范围（负责人最新确认）：** 首个小版本只开发手动技能。自动技能不进入首版实现、不为其增加自动触发逻辑或模式 UI；待小版本完成并验证核心玩法后，再重新研究是否引入及如何设计。此前逐技能独立设置自动/手动的方向暂存为历史讨论，不作为首版要求。

**后续研究备忘（AI 提案，未确认，不属于首版）：** 自动技能未来可研究以下共同判断框架：

1. 技能已解锁/装备且不处于冷却中。
2. 技能所需资源满足要求（资源类型与消耗规则待 D-205/D-206 或技能系统设计确认）。
3. 当前存在符合该技能效果的目标或战场条件。
4. 预计施放能产生有效收益，而不是仅因冷却结束就立即释放。
5. 若条件不满足，保留技能并继续等待；具体是否允许长时间保留、是否存在自动施放超时机制待确认。

**各技能未来自动施放触发思路（仅作备忘，不是已确定规则）：**

| 技能 | 自动模式触发思路（提案） | 仍需讨论的重点 |
|---|---|---|
| 火焰爆炸 | 多个敌人聚集在有效范围内，或高威胁敌人处于爆炸范围时考虑施放 | 最少命中目标数、Boss 单体是否可触发、范围与预判 |
| 闪电链 | 附近存在多个可连锁目标，预期能命中多个敌人时考虑施放 | 连锁数量、跳跃距离、目标选择与单体例外 |
| 冰霜领域 | 多个敌人接近/包围玩家，或近身威胁即将形成时考虑施放 | 危险距离、控制效果、Boss 是否受控及触发门槛 |
| 魔法护盾 | 玩家处于较高受击风险或生命状态危险时考虑施放 | 生命阈值、预判伤害、已有护盾时的处理与持续时间 |
| 闪现 | 玩家被包围或存在明确脱离危险路线时考虑施放 | 自动寻路落点安全性、是否允许自动位移、误闪风险 |
| 生命汲取 | 玩家需要恢复且存在可有效汲取的目标时考虑施放 | 生命阈值、汲取距离、目标优先级及恢复上限 |

**自动技能动态优先级（此前已确认的设计原则，暂缓实施）：** 未来若研究自动技能，可沿用根据当前战场情况动态调整技能优先级、不采用固定释放顺序的方向；但该原则不要求首个小版本实现。

动态判断的情境分类建议（仍为 AI 提案，未逐项确认）：
- 生存压力高、即将被击败或包围时，优先考虑防御/脱险类技能（如护盾、闪现）。
- 多个敌人逼近或形成包围时，考虑控制类技能（如冰霜领域）。
- 敌人聚集且范围收益较高时，考虑群体输出技能（如火焰爆炸、闪电链）。
- 玩家需要恢复且存在有效汲取目标时，考虑恢复类技能（如生命汲取）。
- 即使技能冷却完成，若当前施放收益低或条件不满足，也可以继续等待。

**仍待确认：** 各类战场情境的判断阈值、不同技能之间的具体优先级权重、多个条件冲突时的决胜规则、资源竞争与技能组合策略，以及是否允许玩家调整自动技能倾向。不得将上述示例写成固定的技能优先级表。

**重要边界：** 自动技能属于后续版本研究项，不代表接入外部 AI 服务。首个小版本以手动施放为唯一技能操作方式；上述六种技能及触发思路仅作为未来讨论备忘，技能最终名单、效果、数值、触发阈值、目标规则与优先级均未冻结。
