### 5.1 bus 适配层吞事件是否引入新 bug（重点排查）

- **结算屏不弹风险**：结算屏订阅 `combat.bus` 的 `run.settled`（`src/ui/SettlementScreen.ts:31`）。场景层 `publishSettlement` 的 L470 `combat.bus.publish('run.settled', …)` 直接走 combat.bus，**不经 economyBus**，结算屏能收到 → **不会不弹** ✓
- **重复弹屏风险**：EconomySystem.settleRun 成功时自身也 publish `run.settled`（system.ts:204），但走 economyBus 被吞 → **不会重复弹** ✓
- **Boss 胜利链重入风险**：场景层 victory 时 `economy.onBossDefeated()`（L457）内部 publish `boss.defeated`，走 economyBus 被吞 → **不会二次触发** BossCombatBridge 胜利链 ✓
- **结论**：吞事件设计成立，未发现结算屏不弹或事件重入的新 bug。

### 5.2 关键缺口：结算屏与存档的"经济数据"是断链（DEF-001）

- 场景层 `publishSettlement` 的 loot 是**硬编码全 0**（L464-469，注释"本试玩未接地面拾取"）。
- EconomySystem 的 `pickup()` / `rollDropsForKill()` / `beginRun()` 在 `src/` 中**从未被调用**（grep 确认仅存在于 system.ts 定义处）。
- 后果：`settleRun` 内 `credited = this.ledger.buildRunLoot()` 恒为空 → 金币、宝石、森林材料、元素碎片**运行时不进账**；只有 `stats`（runsPlayed/bossKills/bestTimeSec）与 Boss 胜利的 `forestCore` 会落盘。
- 玩家可见：打完一局，结算屏永远显示 0 金币/0 宝石/0 材料，存档金币不增长（F1 的 gold=55、F2 的统计增长都是直接调 API 证明**能力**，非玩家路径证明**结果**）。
- 定性：非 D-207 引入，属既有"本试玩未接地面拾取"残余；但它使 ADR"真实经济数据完整持久化"的承诺只兑现了统计子集。**不阻塞存档后端本体关闭，但阻塞 D-207 整体承诺关闭。**

- **Category**: Crash/稳定性 / Economy ｜ **Frequency**: Rare（配额触顶时）｜ **Regression**: **Yes（D-207 换真后端后新暴露）**
- **复现步骤**：① 用真 localStorage 填至接近配额 → ② 通关触发结算 → ③ 观察控制台与存档
- **期望**：落盘失败有兜底（catch + 玩家提示 + 不误报成功）
- **实际**：`void economy.settleRun(...)`（BootstrapScene.ts:458）无 catch；`commit`→`store.save` 在配额失败时抛错（E1 已证 adapter 会抛），冒泡成 unhandled Promise rejection；结算屏照弹，玩家以为存档成功，实际本局未落盘
- **技术上下文**：`src/scenes/BootstrapScene.ts:458`、`src/economy/system.ts:285-291`、`src/save/LocalStorageSaveAdapter.ts:86-87`
- **说明**：mock 后端不会配额失败，D-207 换真 localStorage（5MB 硬限）后此风险从理论变现实；建议 settleRun 内 catch 并回报 `commit=false`，或场景层 `.catch()` 提示玩家
- **注**：主档完好（E1 已证协议保护），数据不会损坏，属"漏存+无提示"，非"损坏"

### DEF-003 — SettleRunInput.bossDefeated 死参数 + 绕过模式脆弱（含 beginRun 未接线）
- **Severity**: S4-Low（当前）／潜在 S2（若新增调用点） ｜ **Priority**: P2（随风险1裁定一并处理）
- **Category**: Gameplay / API 契约 ｜ **Frequency**: Always（结构性）｜ **Regression**: No
- **事实**：入参 `bossDefeated` 被忽略；场景层靠 `onBossDefeated()` 显式置位绕过；`beginRun()`（重置 `bossDefeatedThisRun`/ledger）运行时从未调用，仅靠 `location.reload()` 整页重建兜住重置
- **风险**：任何新增 settleRun 调用点若只传 `bossDefeated:true` 而不调 onBossDefeated，会静默丢 Boss 进度/森林核心；同一实例内连续多局时不重置标志会误记 bossKills（当前无此路径）
- **裁定**：随风险1 由主理人裁定，本审查不改 `src/economy/system.ts`

### DEF-004 — economyView() 已暴露但无消费者，ADR 声明与实现不符
- **Severity**: S4-Low ｜ **Priority**: P3-Backlog
- **Category**: UI / Integration
- **事实**：`economyView()`（BootstrapScene.ts:718）全仓无调用；结算屏读 bus payload，重开走 `location.reload()`。ADR"作为 UI / 重开数据源"目前名不副实
- **说明**：不影响功能，属接线未闭环的观察项；若后续 UI 要显示"历史最佳/累计击杀"，此端口已备好

### DEF-005（观察项，暂不判缺陷）— boot/settle 异步 void 的理论竞态
- **Severity**: S4-Observation ｜ **Priority**: P3
- **事实**：boot 与 settleRun 均以 `void` 异步调用；极端情况下（如 `?killboss=1&t=600` 快进在 boot 微任务完成前结算）可能在默认档上结算并覆盖尚未加载的真档
- **说明**：localStorage 读为同步且 boot 为微任务级，实际游玩不可能触发；headless F2 用 `await boot()` 掩盖了该路径。记录备查，不阻塞

**趋势性提示（上报主理人）**：DEF-001/003/004/005 共同指向同一个系统性问题——**EconomySystem 的运行时接线只完成了"存储端"（boot/settle/loadSync），未完成"数据源端"（beginRun/rollDrops/pickup/economyView 消费）**。建议把它作为一条整体技术债立项，而非逐点补丁。
